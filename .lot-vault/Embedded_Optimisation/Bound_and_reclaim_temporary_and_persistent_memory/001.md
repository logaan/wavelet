# Bound and reclaim temporary and persistent memory

The historical counter reserved 1 MiB for persistent state and declared 17 pages before work. Persistent allocation bumps a pointer and traps on exhaustion without general reclamation. Ordinary temporary arenas reset at post-return but can grow within a single call; Wasm memory does not shrink.

Replace the fixed persistent reservation with explicit budgets and a documented lifetime strategy such as resource-owned regions or bounded pools. Support maximum memory and no-growth execution. Reclaim dropped resources and replaced persistent values according to ownership. Audit allocation overflow, failed growth, traps, reentrancy and all resource-method/ordinary-export cleanup paths. Bound temporary allocations within loops and tail recursion, not merely the call stack.

Acceptance: repeated create/use/drop and mutate cycles reach a stable memory plateau; exceeding configured budgets fails predictably without corruption; a simple counter works within a small declared budget; no-growth builds contain no reachable growth path; dynamic strings and aggregates survive ABI/post-return lifetime boundaries correctly. Include long-running stress tests and high-water reporting.
