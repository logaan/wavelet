# Separate minimal Wasm primitives from explicitly imported source libraries

Adopt the user's architectural rule: builtin operations are low-level Wasm building blocks with explicit, predictable cost. Convenience operations belong in an explicitly imported standard library, which can be omitted by embedded programs. Preserve WIT-compatible types and required ABI validation without treating every operation on a WIT type as a Wasm primitive.

Current constraints

- src/builtins.rs globally installs numeric, collection, text, conversion, cell and macro helpers; If and Do are implicitly installed library macros.
- Runtime Import names a WIT interface. Sibling source files compile as distinct components (src/compiler/unit.rs), so current imports introduce canonical ABI boundaries rather than linking ordinary functions into the caller.
- DefFunctor generates concrete declarations, but templates are currently file-local and cannot contain imports or nested instantiation. Existing import syntax therefore cannot simply move generic map/fold into a source library without new compiler work.
- Primitive scalar emission is improving separately. Generic boxed dispatch, implicit int-to-float promotion and normalising narrow WIT types to i64/f64 still obscure the true instruction choice.

Proposed classification

Keep native scalar arithmetic, numeric comparison, boolean negation and explicit conversions whose width, signedness, rounding and trap behaviour match selected Wasm instructions. Keep control flow/calls, locals, WIT construction/projection and resource identity/ownership as language/representation mechanisms, not an implicit convenience library. Record precisely which primitives compile to one instruction and which ABI/representation operations require a small sequence.

Move map, filter, fold, zip, range, reverse, push, concat, head, tail and empty into collections modules. Persistent put is a library algorithm: its current immutable result requires copying unless unique ownership is proven; it is not equivalent to a mutable store. A low-level mutable buffer write must have a distinct ownership and aliasing contract.

Split len by representation: list length is a descriptor projection and tuple arity is static; UTF-8 byte length can be a descriptor projection; Unicode scalar count is a traversal and belongs in the text library. Do not silently change existing len(string) from scalar count to bytes: rename the operations explicitly during migration and update callers.

Move str-cat, split, join, contains, to-string, structural aggregate equality and lexicographic string ordering into text/collections/format modules. Preserve Unicode strings/chars, but include text algorithms only when imported. Resource-backed sets are a library data structure, not a compiler-known special case. Cell construction/lifetime needs an explicit low-level storage primitive or library contract rather than hidden persistent allocation.

Integer negation, abs, min and max have no corresponding single scalar Wasm opcodes (unlike float neg/abs/min/max). They should be ordinary tiny compositional library functions if the one-opcode criterion is literal. Float remainder is being rejected separately because Wasm has no corresponding scalar instruction. Remove implicit mixed numeric promotion or expose conversions explicitly; preserve i32/i64/f32/f64 internally and document WIT narrow integer boundary semantics rather than pretending u8 has a native arithmetic instruction. Stop routing statically typed primitive calls through boxed helpers.

Compile-time form inspection, quoting, macro expansion and gensym belong in the compile-time environment and need not become runtime dependencies. Coordinate with the separate compiled-macro/interpreter-removal work before changing them or implicit If/Do support.

Concrete source-module design recommendation

Add a distinct source-module import form, tentatively Import {module: "wavelet:collections" as: seq}; keep existing Import {pkg: ...} for component interfaces. The exact spelling is a design proposal, not an implemented contract.

A source module contains exportable functions, types and templates, not a separately instantiated component. Resolve an explicitly supplied or bundled module source graph before normal expansion/checking; use lexical namespaces and stable symbol identities, diagnose cycles/missing exports, and retain source spans. Link reachable typed definitions into the importing component's IR. An import alone must not inject runtime imports, memory, helpers, initialisation, or copies. Do not conflate importing source with granting host capabilities.

The compiler API and compiler component must accept the same module graph so the CLI, browser and in-memory compiler behave identically. Standard library source can be bundled in the compiler as a versioned, explicitly selected module set; it is not emitted into programs until referenced. A module can transitively request another source module, with dependencies inspectable and reproducible. Runtime component imports stay explicit and preserve their ABI and resource identities.

Generic collections must specialise by concrete element/result types and statically resolved callbacks. Compile seq/map(f, xs) into a direct loop or specialised local helper; never invoke a component ABI boundary per element and never add a dynamic closure allocation solely because the operation moved to a library. Inline and fuse where safe; preserve callback order, side effects and trap timing. Source import therefore precedes monomorphisation/optimisation, not post-compilation composition.

Missing low-level foundations

- Width/signedness-preserving scalar representations and explicit Wasm conversions; consider bitwise/shift/rotate/count operations where not exposed.
- Typed list/string descriptor projections, typed element load, and explicit bounds/trap policy. A Wasm memory bounds check does not enforce list bounds.
- A bounded typed buffer or region interface for allocation, indexed stores and finalisation; enough to implement map/range/concat without relying on those same high-level builtins.
- Ownership/borrowing or unique-builder rules to allow efficient mutable construction without silently changing immutable list semantics.
- Cross-module generic specialisation and compile-time callback parameters; current file-local type templates alone are insufficient.
- Explicit UTF-8 byte access/validation boundaries for text algorithms and a scalar-count library operation.

First coherent implementation milestone

1. Inventory the current builtin contracts with exact emitted operations and allocation costs; agree primitive names, string length names and immutable versus mutable buffer contracts.
2. Add source-module resolution/linking across native/browser/compiler API, initially with concrete typed functions and source diagnostics. Ship an opt-in small numeric/logic source module for integer abs/min/max wrappers; verify there is no runtime component import and no unused library payload.
3. Add typed list length/get plus bounded builder primitives and module-generic/callback specialisation. Move empty/head and then map/fold as one complete, tested slice. Keep remaining convenience operations temporarily documented until each can be implemented correctly using the approved primitives.
4. Migrate remaining libraries/callers/docs/examples/LSP, remove implicit registrations, and regenerate artifacts. A no-stdlib program must compile with no library imports or support code. Do not merely rename compiler intrinsics behind an import while leaving compiler-known collection algorithms.

Acceptance criteria

- An explicit library import is required for moved conveniences; omitted imports yield actionable missing-name diagnostics.
- Primitive arithmetic of supported Wasm types emits the corresponding instruction without boxing, hidden promotion or overflow niceties. Necessary ABI checks and list bounds policy are explicit.
- list length and string byte length use descriptor projections; Unicode scalar count is visibly a library traversal.
- map/fold in a source library compile into the caller with no canonical ABI hops, callback boxing or avoidable intermediate allocation; output matches handwritten loops for equivalent semantics.
- Pure persistent put preserves aliases; mutable builder store has an explicit distinct contract and predictable bounds behaviour.
- Unused library modules/functions/data add zero emitted code/data/memory. Tests cover collisions, imports, source diagnostics, generics and both CLI/browser compiler paths.
- Regression benchmarks and target feature profiles measure final emitted code, not merely Rust compiler build size.

Dependencies: embedded benchmarks; reachable function/data emission; typed aggregate calling conventions; bounded memory and ownership design; compiled macro pipeline for library macros. Numeric-semantic adoption is active parallel work and is not duplicated here. Open design decisions are the source import spelling, primitive integer widths/signedness and conversion naming, the replacement string-length API, and the safe low-level mutable buffer contract.
