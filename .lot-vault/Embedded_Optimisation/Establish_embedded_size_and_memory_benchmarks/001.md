# Establish embedded size and memory benchmarks

Build a reproducible benchmark corpus and budget reporting before changing representation or allocation policy.

Cover scalar constants, arithmetic and comparisons, recursion, list processing, records, variants, strings, resources, and multi-component composition. Provide handwritten core-Wasm and component baselines with equivalent interfaces and semantics. Record compiler/runtime/tool versions and target features; distinguish raw Wasm bytes, stripped component bytes, AOT bytes, runtime firmware, initial linear memory, peak memory, allocation/copy counts, stack and latency.

Acceptance: one repeatable command produces machine-readable results and human-readable differences; scalar and resource baselines reproduce the new current compiler; CI tracks meaningful budgets; device results clearly identify the board and runtime. Compare required Wasm behaviour, including traps/NaNs/signedness, rather than the removed interpreter reference. Historical sizes in the parent are context, not permanent thresholds.
