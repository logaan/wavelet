# Carry typed aggregate representations through calls

The emitter already has scalar and typed memory representations, but non-scalar local parameters and resource methods often fall back to boxed signatures. This introduces tags, allocation and canonical-layout conversions across local calls.

Represent lists, records, tuples, options/results and variants with statically known layouts across parameters, returns, locals, callbacks and resource methods. Separate internal calling conventions from canonical ABI boundaries. Specialise generic operations at compile time; retain boxing only where the semantics truly require a dynamic representation. Avoid introducing runtime function-value machinery for statically resolved callbacks.

Acceptance: typed aggregate pipelines do not allocate solely to cross a local call; type-specific loads/stores replace generic tag dispatch; nested aggregates, variants and resources remain correct; compare instructions, allocation counts and bytes against handwritten equivalents. Define and test ownership/aliasing before enabling borrowed or shared views.
