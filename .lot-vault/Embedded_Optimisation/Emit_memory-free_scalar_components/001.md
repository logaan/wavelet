# Emit memory-free scalar components

Scalar-only exports currently receive unconditional memory, realloc, globals, static data and post-return functions. External optimisation retains exported or observable infrastructure.

Determine memory and cleanup requirements from reachable program behaviour and actual canonical-ABI signatures. Omit linear memory, cabi_realloc, allocation globals/data and post-return cleanup when unnecessary. Avoid extra export wrappers where direct export preserves ABI behaviour.

Acceptance: a component returning 42 and scalar arithmetic components validate and execute with no linear memory, allocator or cleanup; their scalar bodies match handwritten equivalents; complex imports/exports that require memory keep correct ABI support. Compare the same WIT interface and metadata policy against handwritten baselines, targeting hundreds rather than thousands of bytes for trivial components.
