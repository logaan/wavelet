# Integrate release optimisation and target feature policy

Experimentally, Binaryen -Oz shrank a historical constant core from 6,286 to 510 bytes. Repackaging and stripping yielded a 702-byte component. This is not yet a supported build pipeline.

Design an explicit size/speed/debug policy, optimise core modules before componentisation, and strip only optional metadata after packaging. Pin optimiser/tool versions and specify enabled Wasm features rather than using the experiment's --all-features. Preserve component metadata needed for construction and resource/canonical ABI contracts. Consider how native CLI and compiler component/browser pipelines get equivalent behaviour without mandatory undeclared host tools.

Acceptance: release outputs validate and pass independent expected-result, Wasm semantic, component and browser tests; declared feature profiles are enforced; optimiser absence/failure is deterministic and documented; benchmark results distinguish DCE, simplification and stripping gains. Do not rely on wasm-opt alone to remove exported allocator support or unreferenced bytes in live data segments.
