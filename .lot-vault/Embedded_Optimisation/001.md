# Embedded Optimisation

Make compiled Wavelet suitable for embedded systems, with overhead close to handwritten WebAssembly implementing the same semantics and interfaces.

This is the backlog for optimisation work beyond the active changes to remove Unicode casing, adopt Wasm numeric semantics, remove the interpreter as reference, and split convenience functions into an explicit standard library. Those active changes are not duplicated here.

Research baseline: checkout d5417d5 on 2026-11-12. A component returning 42 was 6,870 bytes, or 702 bytes after optimising its extracted core with Binaryen -Oz and stripping metadata. A handwritten implementation of the same WIT interface was 225 bytes stripped and required no linear memory. The current scalar component required 64 KiB. A counter resource was 8,169 bytes but declared 17 memory pages (1,088 KiB) due to a 1 MiB persistent reserve. These are historical measurements: rerun after current language changes.

Success means measuring component/core bytes, device runtime footprint, initial/peak memory, allocations, copying, stack and latency independently. Preserve the newly adopted Wasm semantics; do not optimise away required traps or interface validation. No claim of hard real-time readiness without bounded resource and timing evidence on selected hardware.

Suggested order: baselines; reachable code/data and memory-free scalars; optimiser/feature policy; bounded persistent memory; typed aggregate calls and copy elimination; target validation and composition optimisation. Dependencies and acceptance criteria live in the children.
