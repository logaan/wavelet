# Optimise internal component composition boundaries

Current sibling-file composition connects Component Model imports/exports and can preserve allocation/copying at canonical ABI boundaries. A zero-overhead goal must distinguish required isolation/interfaces from internal organisational boundaries.

Investigate whole-program composition optimisation, static linking or component fusion for known internal components where isolation is not required. Eliminate unused exports/imports and redundant lift/lower/copy operations when semantics permit, while preserving public WIT identities, resource ownership, host requirements and validation.

Acceptance: an internal multi-file scalar/aggregate pipeline approaches an equivalent single-component baseline; public interfaces remain identical; resource identity/destruction and canonical boundary rules remain correct; optional optimisation is documented and benchmarked against isolated composition. Do not silently share memory across boundaries that promise isolation.
