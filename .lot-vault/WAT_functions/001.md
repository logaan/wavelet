# WAT functions

I'm considering adding a new type of function to Wavelet. These functions would have definitions that are the same as the existing wavelet functions but their body would be written in WAT.

The purpose of this change would be to reduce the size of the core language. I expect that if we can drop down to almost raw webassembly that the language will need fewer builtin functions. Fewer builtins means that more functionality can be moved out into a standard library component that is just composed into a wavelet program, and potentially able to be swapped out by users who have different ideas about what a standard library should contain.

The WebAssembly Text Format (WAT) is the human-readable, textual representation of the binary WebAssembly (.wasm) bytecode. It is structured as an assembly language that uses S-expressions (Symbolic Expressions), which represent nested tree structures using parentheses.

I don't want you to implement anything. Just check out the codebase and see what kind of impact you think a change like this would have.

1. Would it shrink the core much?
2. Would it introduce potential foot guns for wavelet users?
3. Would it unlock more powers for wavelet users?

My thought is that for an early implementation the contents of these WAT functions would be parsed, but not compiled by wavelet. Instead wavelet would make use of wat2wasm (or the libraries that wat2wasm is built on top of, if they're available).
