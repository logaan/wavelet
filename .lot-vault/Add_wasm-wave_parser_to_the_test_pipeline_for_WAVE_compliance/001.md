# Add wasm-wave parser to the test pipeline for WAVE compliance

# Verify WAVE compliance with the official wasm-wave parser

## Why

Wavelet's `to-string`/`print_value` output is documented as "canonical WAVE
text", but nothing in the test pipeline actually checks it against the WAVE
spec — we only check the two pipelines against *each other*. A hand audit
against the WAVE EBNF (wasm-tools `crates/wasm-wave/wave_ebnf.md`, done
2026-07-28 during 0.2) already caught one real deviation: Rust's `{c:?}`
spells NUL as `'\0'`, which is not a WAVE escape (fixed — we now print
`'\u{0}'`). Known deviations that a mechanical check would keep honest:

- **unit prints `{}`** — WAVE spells the empty record `{:}`; `{}` is the
  empty *flags* value.
- **empty tuple prints `()`** — WAVE tuples require at least one element
  (only reachable via homoiconic forms; WIT has no 0-tuples).
- **strings containing NUL** — the `{s:?}` oracle spells NUL `\0` (and
  `\u{0}` before a digit), not WAVE.

## Proposal

The official WAVE implementation is the `wasm-wave` crate in
`bytecodealliance/wasm-tools` (`crates/wasm-wave`): a parser + writer, the
same one wasmtime uses for CLI value I/O. Add it as a dev-dependency and
bolt a compliance leg onto the existing suites:

1. In `tests/differential.rs` (or a sibling `tests/wave_compliance.rs`):
   for every documented example's printed value, assert
   `wasm_wave::from_str::<wasm_wave::value::Value>(ty, text)` parses — i.e.
   everything Wavelet prints is *parseable* WAVE, not just self-consistent.
   Untyped parsing (`wasm_wave::untyped::WasmValue`? check current API) may
   be simpler where we don't have a WIT type handy.
2. Feed the `tests/backend_to_string.rs` float/char vectors through the
   same check (they cover the exotic corners: subnormals, `\u{..}` escapes,
   scientific notation).
3. Where we *knowingly* deviate (unit `{}`, above), either fix the printer
   or record the deviation in a small allowlist next to the test so the gap
   is documented and ratcheted like the differential SKIP list.

Cost: one dev-dependency (wasm-tools is already in-tree as a dependency
family), a few dozen lines of test. Payoff: "desugared Wavelet output is
WAVE" becomes a checked invariant instead of a claim.
