=== SEAM RECON (what "retirement" actually means here) ===

The backend carries TWO representations, and the canonical one is an OVERLAY:
  - BOXED: TAG_* tagged heap objects (emit.rs:54-65). `expr()` (emit.rs:1544)
    produces a box for EVERY node kind; it is the universal fallback.
  - CANONICAL Repr::Mem: headerless ABI layout, built up over sessions 3-11. Only
    "provably faithful" constructions go canonical (can_mem_as emit.rs:5200,
    mem_field_ok 5286, node_mem_ty 5331, predict_body_mem 5382); everything the
    gradual checker leaves Unknown, and every node kind with only a boxed producer,
    stays boxed.

The SEAM functions:
  - load_from_mem (emit.rs:4359): canonical -> box. This IS "rebox." Fires when a
    Mem binding is used by expr (emit.rs:1578) or by any builtin that consumes its
    operand via `self.expr(...)`.
  - store_to_mem (emit.rs:4143): box -> canonical (the optimistic variant/flags
    path).
  - expr_mem (emit.rs:5444) / expr_mem_into (5549) / mem_field_into: construct
    directly in canonical layout, no box.

The BOX CONSUMERS (code that READS a TAG_* box): the boxed pattern matcher
`pattern` (emit.rs:3024, string-compares TAG_VAR case names at 3034-3042); the
boxed builtin helpers (eq_raw, len_raw, head_h, tail_h, strcat2, to_str,
arith_raw, accessors); and the boundary LOWER (store box -> flat ABI).

=== THE HONEST ORDERING CONSTRAINT (a real finding, not a deferral) ===

WHOLESALE TAG_* deletion is NOT landable now; it is gated on two things this plan
does not build:

(1) TOTAL TYPING (goal 3). While the checker is gradual, `expr()` MUST keep
    producing boxes: it is the fallback for every Unknown-typed value and for node
    kinds that have only a boxed producer (Node::Int/Str/Char literals feeding an
    untyped context, list_box, rec_box, flg_box, closures). A box CONSUMER cannot
    be deleted while any producer feeding it can still be boxed. So you can only
    SHORTCUT specific (producer-canonical -> consumer-canonical) paths PAST the
    box; you cannot remove the box path. The consumers finally retire when total
    typing removes the last boxed producer feeding each — that is a goal-3 exit,
    not a goal-5 slice.

(2) 5.8 DEFUNCTIONALIZATION. TAG_FN (closures) and the TAG_TUP arg-bundle calling
    convention that rides on it (payload_box bundles >=2 args as TAG_TUP,
    def_wrapper_slot/fn_form unpack it — session 6, 83387f6) cannot retire until
    closures become plain WIT variants. So TAG_FN and a large share of TAG_TUP use
    are blocked on 5.8, which is out of scope this session.

CONCLUSION: the deliverable is NOT "delete TAG_*"; it is a stream of canonical-path
shortcuts that each shrink reboxing along one proven-canonical path (leaving the
box path intact as the gradual fallback), PLUS the 5.1 evacuation glue (which is a
resource-STATE-persistence concern, largely orthogonal to TAG retirement, with its
own dependency spelled out in slice 5). The terminal wholesale deletion is
recorded here as gated on goal-3 + 5.8, so a later session does not re-discover it.

--- SLICE 5: 5.1 evacuation glue + functor/resource opt-out removal ---
  *** THIS IS THE LEAST BACKGROUND-SAFE AND HAS A REAL DEPENDENCY — ordered last. ***
WHAT: today components with functors OR user resources OPT OUT of the arena reset
  (emit.rs:7312 `if info.functors.is_empty() && info.resources.is_empty()`) and keep
  never-free behaviour, because resource state (the set functor's TAG_CELL over a
  TAG_LIST; a user counter's New cell) lives on the arena and must survive across
  export calls. The 5.1 design (5.1 Thing update 007, lot:033j0CfiXzfgP5nzT8dmjW) is
  EVACUATE-AT-POST-RETURN: a persistent floor grows up from the heap base, the arena
  above it; at post-return the reset walks the resource-table roots, DEEP-COPIES
  their reachable state down to the persistent floor, advances the floor, resets the
  arena to it. Then the opt-out at emit.rs:7312 is removed.
THE DEPENDENCY (spell it out): the 5.1 design assumes "type-driven copy glue: sizes
  and layouts are static once 5.3/5.5 land" — i.e. it assumes the resource state is
  CANONICAL. But it is STILL BOXED today (emit_set_resource keeps a TAG_CELL/TAG_LIST
  heap graph; user New cells are boxes). So the evacuation copy is EITHER:
    (5a) a general BOX-GRAPH relocator (walk TAG_CELL -> TAG_LIST -> element boxes,
         relocate each, fix up pointers) — works today but is a wide-blast-radius,
         instrumentation-only, pointer-rewriting routine that touches every TAG
         layout; OR
    (5b) FIRST canonicalize resource state (rework emit_set_resource + user-resource
         New cells to store canonical layout), THEN the type-driven copy is a flat
         static-size memcpy per root. Cleaner, but "canonicalize resource state" is
         itself a substantial sub-project (the resource machinery, not the value
         seam).
  RECOMMENDATION: do slice 5 as its OWN dedicated session (like 5.7), not as a
  background ride-along. Prefer path 5b (canonical resource state, then flat
  memcpy evacuation) because it aligns with the goal-5 direction and avoids a
  bespoke box-graph relocator that would itself need retiring later. If pursued
  earlier via 5a, gate it behind an env flag and prove correctness with a
  multi-call resource test (set add/size across >2 export calls with an arena reset
  between) before removing the opt-out.
SITES: emit.rs:7285-7325 (post-return emission + the opt-out guard), emit_set_resource
  (~6957), the user-resource New cell emission, the arena-floor globals (7311/7558).
BLAST RADIUS: GLOBAL — changes resource-state lifetime across every functor/resource
  component; the conformance resources callee is the gate. NOT behavior-preserving
  in the trivial sense (it changes WHERE state lives) — needs the multi-call test +
  full resources-callee conformance both directions.
VERIFICATION: a component that instantiates a set (or user counter), calls a
  mutating op then a reader op across TWO export calls (forcing a post-return reset
  between), asserts the second call sees the first's state; resources callee PASS
  both rust callers with the reset ENABLED for resource components.
DEPENDS ON: canonical resource state (5b) OR a box-graph relocator (5a).
DEPENDENTS: closes the 5.1 Thing.
