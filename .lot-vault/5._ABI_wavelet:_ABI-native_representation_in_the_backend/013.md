COMMIT 7040ad2 (check: thread declared export result type into bodies +
Option-A int widening). Implements exactly Logan's Option-A decision:

- check.rs collect() gathers each Export's declared `result:` type
  (as_export_result helper -> export_results map, concrete/non-Unknown only).
  check_roots() threads it into the matching def's body as the `expected` type
  (both the Fn-with-params branch and the bare-value branch); previously bodies
  were checked with expected=None. This is what lets construction sites build at
  their declared shape (canonical record/variant/flags field order + flags bit
  positions -- the linchpin session 6/7 flagged) and is the precondition for
  5.6's cross-origin canonical compound ops.
- compatible_widening() (NEW) is used ONLY at the check() boundary validation
  and resolve_overload step-2 result filter. args_match() KEEPS strict
  compatible() so overload argument filtering does not widen into ambiguity.
  * int_widens/int_class: same-signedness narrower->wider (s32->s64, u16->u64)
    admitted; mixed signedness (s32<->u32, both ways) and narrowing (s32->s16)
    rejected -- exactly Option A.
  * payload-less result-arm dropping: a value carrying a result payload (ok(0))
    flows into a declared payload-less `result` because the ABI drops the
    payload. A PRESENT declared arm still checks strictly (an s32 payload does
    not narrow into an s16 ok arm).
- Return-type-directed overload resolution now applies in export bodies too;
  oracle-consistent by construction because resolve_overloads shares the same
  check_roots walk the interpreter runs.
