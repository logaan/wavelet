# Decision: qualified case constructors (`t/east(5)`)

Decision brief for the 5.4 residue "dep Qsym ctor calls stay boxed" (goal-5
sessions 10/11 escalated it here as a language question). **No code has been
changed** producing this brief; everything below was verified against the
current tree (interp repl + reading emit.rs/interp.rs/runner.rs + the existing
tests).

## 1. Context — how variant/enum cases are constructed TODAY

There are three candidate spellings. Two work; one does not. The residue
conflated them, so this brief separates them precisely.

### Spelling 1 — bare case constructor (WORKS everywhere)

`DefType` binds each case into the *value* namespace: a nullary case as a
payload-less variant value (like `none`), a payloaded case as a constructor
(`interp.rs` `deftype-MACRO`, ~305-325: `env.define(case, Value::CaseCtor(..))`).

```wavelet
DefType direction [north east south west]
DefType ttl [days(u32) forever]
east            // => the enum value `east`
days(5)         // => variant value days(5)
```

Verified in the repl: `to-string(east)` … `to-string(days(5))` => `"days(5)"`.
The backend constructs these natively: `ctor_parts` (emit.rs:5075) matches a
`Node::Sym` head, and `ctor_admissible`/`can_mem_as` build the canonical
discriminant+payload (Repr::Mem) layout (5.4). Test:
`tests/case_constructors.rs::backend_constructs_enum_and_variant_cases`.

### Spelling 2 — import-alias-qualified case constructor (WORKS, but stays BOXED in the backend)

When a sibling package's `DefType` is imported, its cases are reachable through
the **import alias**:

```wavelet
Import {pkg: "demo:shapes/api" as: sh}   // shapes.wlt declares DefType shape [circle(f64) dot]
sh/area(sh/circle(2.0))                   // sh/circle(2.0) constructs the imported case
```

- Interpreter: the runner binds each dep `DefType` case under `alias/case` into
  the module env (`runner.rs`:216-225, `env.define(format!("{alias}/{case}"), ..)`).
  `Node::Qsym` evaluation (`interp.rs`:89) is a *plain env lookup* of
  `"sh/circle"`, which now finds the `CaseCtor`. So the plain-lookup site has no
  special case logic — the binding was pre-installed at import time.
- Backend: `call`'s `Node::Qsym` arm (`emit.rs`:2429) routes to `dep_call`;
  `dep_call` (emit.rs:3344-3377) tries `resolve_dep_func`, and on a miss falls to
  `dep_case(dep, fname)` (emit.rs:3271) → `var_box` (a **TAG_VAR box**).

This is a working, tested path
(`tests/case_constructors.rs::dep_cases_bind_under_the_import_alias`). **But**
the backend leaves it *boxed*: the 5.4 canonical construction gate `ctor_parts`
(emit.rs:5075) only matches `Node::Sym` heads, never `Node::Qsym`, so
`sh/circle(2.0)` never builds in canonical Repr::Mem layout. THIS — a missed
canonical-construction optimization on an otherwise-correct value — is the
literal "dep Qsym ctor calls stay boxed" residue (5.4 Thing updates 004/010).

### Spelling 3 — type-qualified case constructor (DOES NOT EXIST)

Qualifying a case by its **variant TYPE name** does not resolve at all:

```
> direction/east      // error: unbound qualified name `direction/east` (missing import?)
> ttl/days(5)         // error: unbound name `ttl/days` in call position
```

(Both verified in the repl on the current tree.) Nothing binds `direction/east`;
`interp.rs`:89's plain Qsym lookup fails, and emit's `Node::Qsym` arm routes to
`dep_call`, which finds no import alias named `direction`. This spelling — "case
`east` of variant type `t`", i.e. `t/east(5)` — is the genuine language gap.

### Correcting the session-10 record

Session 10 (goal-5 Thing, update 018) concluded "NEITHER the backend nor the
interpreter has case-constructor resolution for qualified names, and no
test/example exercises the spelling." That is **imprecise**: import-alias
qualification (spelling 2) DOES resolve, works end-to-end, and is tested — it
just stays boxed in emit. What genuinely doesn't exist is **type**-qualification
(spelling 3). The `t/east(5)` residue therefore mixes an emit canonical-codegen
gap (spelling 2) with a nonexistent language feature (spelling 3).

### How `counter/sum(vs)` relates (the template AND the conflict)

DefResource (4.5) already establishes a **type-qualified Qsym call**:
`counter/sum(vs)` calls the `sum` static of resource type `counter`.

- Interpreter: `defresource-MACRO` binds `counter/sum` under its qualified key
  into the env (`interp.rs`, ~365-380), so the plain Qsym lookup finds it.
- Backend: `dep_call` has a `user_res` branch (emit.rs:3337-3342) — if `alias`
  names a user resource and `fname` is one of its methods/statics, it routes to
  an internal call instead of an import.

So `counter/sum` is the closest existing precedent for spelling 3 — but it
resolves against a **resource** type's member table, not a variant type's cases,
and it is installed by DefResource specifically. It is also the closest
**conflict**: a type-qualified case would make a variant type name a member
namespace on `/`, the same namespace import aliases and resource types already
occupy.

## 2. The question

Should Wavelet gain **type-qualified case constructors** — `t/east(5)` meaning
"case `east` of variant/enum type `t`" (spelling 3) — as a language feature? And,
separately/narrower, should the existing import-alias-qualified constructor
(spelling 2) get a **canonical Repr::Mem fast path** in the backend?

## 3. Options

### (a) Drop it — not a feature (PRIOR RECOMMENDATION)

Cases are already constructible two ways (bare; import-alias-qualified).
Spelling 2 stays correct-but-boxed (a marginal, never-observed missed
optimization). Spelling 3 stays unspelled. Reword/strike the "dep Qsym ctor"
item from the 5.4 residue lists.

- Cost: zero code. Blast radius: none. This is what sessions 10/11 recommended.

### (b) Adopt type-qualified case constructors as a language feature

`t/east(5)` / `t/east` resolve to case `east` of the in-scope variant/enum type
`t` (local `DefType` or imported).

- Semantics/oracle first: `interp.rs` Qsym resolution (:89 step, :123 step_call)
  must, on a plain-lookup miss, consult a name→TypeDef map: if `alias` is a
  variant/enum type in scope and `name` is one of its cases, produce the
  CaseCtor / nullary Variant. The tree-walker does NOT currently thread type
  declarations into eval (DefType binds cases, not the *type name* as a
  namespace), so this is real new plumbing.
- Checker: type-qualified case exprs type as the nominal variant (mirror the
  existing bare-case rule in `check.rs`).
- WIT: no change (cases aren't WIT-named entities; the value lowers to the same
  variant).
- Emit: `call`'s `Node::Qsym` arm (emit.rs:2429) currently *unconditionally*
  routes to `dep_call`; it must first test whether `alias` is a local/dep
  variant TYPE and route to case construction (`var_box`, or canonical via
  `ctor_parts`/`can_mem_as` extended to Qsym heads).
- **Ambiguity — the crux.** `t/east` collides with (i) an imported function
  `east` from a package aliased `t`, and (ii) a resource member if `t` is a
  resource. Two names `t` (an import alias AND a variant type) collide. A rule is
  required: either forbid a variant type sharing a name with any import/resource
  alias and fix a precedence for `/` (import alias → resource → variant type), or
  — cleaner — do NOT overload `/` and reject the collision outright. This design
  cost is the main reason to be cautious.
- Testing: interpreter oracle tests first (type-qualified bare/payloaded/nullary
  + ambiguity errors) in `tests/case_constructors.rs`; then backend agreement
  (component tests); a documented example → `./scripts/regen-examples.sh`;
  conformance if cross-component. CHANGELOG Added; docs prose
  (`docs/docs/language/type-system.mdx`). Grammars: **no change** (no new token
  class — `/` and names are unchanged). LSP: optional `t/`-case completion.
- **Recommendation: NOT recommended** absent a concrete motivating program. It
  is a third way to spell an already-constructible value, it overloads the very
  `/` namespace that `counter/sum` and import aliases already contend for, and it
  buys nothing the bare/import-alias spellings don't. High design cost (ambiguity
  rules), low value.

### (c) Narrower — canonical fast path for spelling 2 only (pure optimization, no language change)

Extend `ctor_parts` (emit.rs:5075) + `can_mem_as` (emit.rs:5161/5197) to accept
a `Node::Qsym` head whose `fname` resolves via `dep_case` to a case of the dep's
variant/enum type, so `sh/circle(2.0)` builds in canonical Repr::Mem layout
instead of a TAG_VAR box.

- Behavior-preserving (like the other 5.4 canonical slices): needs
  instrumentation, not diff tests; no oracle/semantics/WIT/docs/grammar change;
  no CHANGELOG (internal). Blast radius: emit only. This is the LITERAL 5.4
  residue as originally written.
- **Recommendation:** worth doing only if import-alias-qualified case
  construction shows up on a hot path. Session 12's retirement study found the
  whole canonical-construction queue is otherwise gated on total typing / 5.8, and
  session 11 judged marginal result-box shortcuts "buy ~nothing," so this is
  low-value in isolation — best folded into the later box-retirement work if ever.
