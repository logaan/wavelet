Design chosen (recorded from the actual code): rather than a semispace copying
collector or a bespoke box-graph relocator walked at post-return (5a) or a full
canonicalization of resource state (5b literal), I used a PERSISTENT-REGION +
DEEP-COPY WRITE-BARRIER, which reaches the same payoff (resource state survives
the per-call arena reset) with far less risk to the passing conformance:

- Resource/functor components reserve a persistent region [heap_base,
  arena_floor) below the arena; the arena bump ptr (global 0) starts at and
  resets to arena_floor = heap_base + PERSIST_RESERVE (1 MiB); a new persistent
  bump global (3+n) grows up from heap_base and is never reset. Non-resource
  components reserve zero (layout unchanged).
- persist_alloc(n): bump the persistent region (traps on reserve overflow).
- persist(box): deep-copy a boxed value graph OUT of the arena INTO the
  persistent region; interned/already-persistent nodes (box < arena_floor) are
  kept in place, arena nodes copied and children re-persisted recursively (null
  persists to null). Handles every value tag; traps on TAG_FN.
- Write barrier wired at the four resource-state store sites: cell-new (cell +
  value persistent), cell-set (value through persist), functor set ctor (cell
  persist_alloc'd, empty list persisted), set add (grown list persisted so only
  the new element is copied, already-persistent elements kept).
- Cells are persistent-from-birth so their identity (the rep the handle points
  at) is stable — no cell-moving, no registry, no post-return walk.
- Then REMOVED the functor/resource arena-reset opt-out: every component now
  resets its arena at post-return.
