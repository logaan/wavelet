Design note closing the open rider (the persistent region for resource
state), after working the allocator geometry:

A separate persistent bump region cannot coexist with the per-call arena in
one linear memory without either relocation-on-grow (down-growing region),
fixed reservations (arbitrary trap budgets), page-chunk fragmentation that
breaks the arena's contiguity, or multi-memory (toolchain risk). The clean
answer falls out of goal 5's own machinery instead:

**Evacuate at post-return.** The persistent floor grows up from the heap
base; the per-call arena sits above it. During a call, resource state
mutates freely in the arena. At post-return — when nothing else is live —
the compiler-generated reset walks the component's resource table roots
(today: each set's cell), deep-copies their reachable state down to the
persistent floor (type-driven copy glue: sizes and layouts are static once
5.3/5.5 land), advances the floor, and resets the arena pointer to it. A
call that touches no resource state pays nothing beyond today's pointer
reset. This is a two-space evacuation with exactly one root set, no
headers, no budgets, no relocation of dead data — and it is only writable
once canonical layout gives every type a computable copy, which is why the
functor opt-out stays until 5.3/5.5.

So 5.1's remaining work is mechanically coupled to 5.3/5.5 by design, not
by omission. The Thing stays open with this note as the recorded plan.
