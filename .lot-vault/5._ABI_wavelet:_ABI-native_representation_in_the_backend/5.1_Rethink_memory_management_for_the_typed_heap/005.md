Decision taken (delegated to the agent by Logan's update 004 "You decide"):
**Option 1 — arena-per-call, headerless everywhere.** Rationale as recorded in
update 002: 2.3's defunctionalization leaves zero non-ABI residue, component
instances are short-lived, and canonical layout then holds unconditionally.
Options 2-4 are rejected for the reasons already recorded.

Concrete shape, from reconnaissance of emit.rs on main (1beb034):

1. **Two bump regions, no headers in either.** A *per-call arena* that resets
   at export-call ENTRY (not return, so a compound result stays readable while
   the caller lifts it — same lifetime the canonical ABI gives a post-return
   window), and a small *persistent region* for state that must survive across
   export calls. Both are bump allocators; neither writes tags or headers;
   static types drive all layout.
2. **What lives in the persistent region:** resource-owned state only. Today
   that is the set functor's cell + its stored list (emit_set_resource keeps a
   heap pointer alive across calls — under a per-call arena that state must not
   be in it); cells join it if/when the backend grows cell support. Persistent
   allocations are explicitly chosen by the resource machinery; everything else
   defaults to the per-call arena.
3. **Value defs (Def of a value) recompute per call.** They are lazily cached
   in globals as heap pointers today; under per-call reset the cached pointer
   would dangle, so the cache globals reset with the arena. Value defs are pure
   in the backend (no cells there yet), so recomputation is semantics-neutral.
4. **Interned statics** (string literals, none-like boxes) are laid out below
   the heap base at emit time and are untouched by resets.
5. Accepted failure mode, unchanged from update 002: a single export call that
   allocates unboundedly. The escape hatch (in-call region-reset points) stays
   open and needs no layout change later.

Implementation lands with the goal-5 layout work on branch goal-5-abi-backend.
