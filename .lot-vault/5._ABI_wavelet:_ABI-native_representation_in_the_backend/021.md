KEYSTONE. New recursive comparator `emit_mem_eq(fx, ty, a, b, off)` leaving i32,
gated in the `eq` builtin arm by node_mem(a)==node_mem(b) && mem_eq_eligible(ty)
(mirrors the len/head gate). Arms:
  - scalars: width-appropriate load on each side + {I32,I64,F32,F64}Eq
  - Record/Tuple: I32And of every field compared at record_field_offsets offsets
    (empty record -> const 1)
  - Option/Result/Variant/Enum: load 1-byte disc each (I32Load8U, matching
    load_from_mem/the <=256-case gate), If discs eq -> compare active case
    payload via emit_variant_payload_eq chain (mirrors load_variant_chain), Else 0
  - Str: byte-len eq (I32Load off+4) then emit_bytes_eq (I32Load8U memcmp loop
    with Block/Loop/BrIf) — NB canonical Str len IS byte length, and byte eq is
    string eq, so this is correct (unlike `len` where string len is char count)
  - List: elem-count eq then emit_list_eq (loop recursing emit_mem_eq per element
    at elem_size(elem) stride)

=== item 2 remainder — tail / str-cat: ANALYZED, DELIBERATELY NOT LANDED ===

Neither has a real win in the BOXED builtin path, so I did not add risk for
marginal gain:
  - `tail` returns a boxed list of elements [1..]. A canonical fast path would
    still have to box n-1 elements (lift_list-style loop) to produce the TAG_LIST
    box the boxed path expects; it only avoids boxing element[0]. The genuine
    zero-copy win (result = (dataptr+stride, len-1) sharing the backing buffer)
    only exists in the expr_mem/Repr::Mem RESULT path, which needs tail wired into
    expr_mem + predict_body_mem + can_mem_as (a bigger change) — do it WITH the
    5.1 evacuation/canonical-result work, not as a boxed-path slice.
  - `str-cat` operands rebox cheaply (a canonical string reboxes to a TAG_STR box
    that just wraps the existing (ptr,len) without copying bytes), so strcat2
    already avoids a copy on the operands; a canonical fast path buys ~nothing and
    adds variadic + char-operand complexity. Skip until the box representation is
    actually being retired.
