First cut landed with the 5.2 typed-scalar path (59523e1): arithmetic with
statically-typed operands now resolves its int-vs-float path at COMPILE time
(runtime tag dispatch gone at those sites), computing unboxed on wasm locals/
stack. Deliberate deviation from this Thing's title, recorded for review: the
int path stays ONE checked-i64 core (shared helper arith_int, also called by
the boxed arith_raw so the two paths cannot drift) rather than per-width
i32.add/i64.add ops — the interpreter models every integer type as Value::Int
(i64) with checked arithmetic, so per-width wrapping ops would DIVERGE from
the oracle (e.g. u8 200+100 = 300 as i64, not 44). True per-width ops become
possible only if the language ever defines per-width overflow semantics —
that would be a semantics change needing its own decision, not a backend one.
f64 ops ARE emitted directly (single instructions). What remains here:
constant folding was not attempted, and comparison still routes through the
shared cmp_f64 core (f64-widened, matching the interpreter's compare).
