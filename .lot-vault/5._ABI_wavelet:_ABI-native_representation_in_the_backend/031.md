=== 5.8 MULTI-CASE VARIANT+DISPATCH: ANALYZED, DELIBERATELY DEFERRED ===
Not built this session, on a value/risk judgment recorded here so session 16
can confirm or override: multi-case dispatch (distinct function values flowing
into ONE binding, e.g. `Let {f: If c inc double} f(x)`) is currently handled
CORRECTLY by the boxed TAG_FN path (each function value is a boxed closure,
applied via closure_call). Building the variant+dispatch representation now,
BEFORE TAG_FN retirement, would require representing those function values AS
the generated variant (discriminant+captures) instead of boxed closures — a
representation change at the join point (the If) that ripples, and it would sit
ALONGSIDE the still-present boxed path with a coercion between them. Net: added
complexity, ZERO observable change, and NO retirement (retirement is gated on
this PLUS total typing per the session-12 plan). It therefore belongs WITH the
TAG_FN/TAG_TUP retirement in the 5b evacuation session, not as a standalone
slice that adds dead parallel machinery. The zero-capture and single-case (and
now capture) devirtualizations that DO pay off immediately are all landed.
