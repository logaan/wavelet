=== THE DESIGN (differs from the session-9 sketch — read this) ===
If/Do are now ordinary macros, authored in Wavelet and installed into the
builtins env by `builtins::install` (new const STDLIB_MACROS + install_stdlib_
macros). Because they live in the env like any DefMacro:
  * the interpreter's lazy runtime expansion (step_call -> env lookup ->
    Value::Macro -> expand_once) rewrites them at eval time — this MATTERS
    because eval_snippet (playground + examples.json) evaluates the ORIGINAL
    (pre-expand) tree, so a pure expand_file rewrite would NOT have reached it;
  * expand_file's expand_form already expands any Value::Macro found in the
    seeded env, so check/wit/emit (which run post-expand) only ever see Match.
Both paths therefore agree "by construction".

Expansions (Match is the sole core branching construct):
  If c t e      =>  Match The bool c [(true t) (false e)]
  Do [e1..en]   =>  nested Match ei [(_ ...)]; single -> the elem; empty -> {}
The `The bool` on the condition gives the bool-check AND makes the true/false
match exhaustive. Do uses a one-step recursive macro (head/tail/empty over the
stmts form + Quasi/Splice), terminating as tail shrinks; wildcard `_` is
irrefutable so exhaustive over any statement type.

AUTHORING GOTCHA (recorded for reuse): you CANNOT write `DefMacro If ...` in
Wavelet source — the reader parses the name `If`/`Do` as a call to the already-
registered arity head of the same name ("unexpected end of input"). So the
macro Value::Macro closures are built in Rust from the BODY source only (which
reads fine because Do is registered). Also: `(The bool Unquote(c))` reads as a
1-tuple wrapping the The-call (double-paren) -> "call head must be a name"; drop
the parens and let Match's arity-driven read consume `The bool Unquote(c)`.

Special-form handling REMOVED from all five stages:
  reader.rs  — UNCHANGED (arity table keeps if-MACRO 3 / do-MACRO 1; the reader
               still needs arity to parse the TitleCase sugar — this is syntax,
               not semantics).
  interp.rs  — if-MACRO/do-MACRO special_form arms deleted.
  check.rs   — infer_special arms deleted (fall to the gradual user-macro path
               pre-expand; the 3.6 post-expand check types the Match); removed
               if/do from the strict_exempt list and the now-unused expect3.
  wit.rs     — if/do return-type inference arms deleted (Match's arm covers it).
  emit.rs    — if_form/do_form + their 3 repr dispatch sites deleted;
               predict_body_mem GAINED a match-MACRO arm so a former If-bodied
               function returning a canonical record still predicts Mem (not a
               boxed fallback).

DIAGNOSTICS (no worse): a non-bool If condition is still a COMPILE-TIME error.
`If 1 t e` -> "eval error: The: 1 does not conform to type `bool`" (was "If
condition must be a bool"). To make that fire I strengthened check_the: an
int/dec literal ascribed to a concrete non-numeric type (`The bool 1`) is now a
static "does not conform" error — it previously slipped through the range-only
check and would have degraded to a RUNTIME "no Match clause for 1". This is a
genuine, correct improvement to `The`, guarded to stay permissive for
numeric/gradual/Named/tree targets (no test ascribes a literal to a non-numeric
type). The one locked example that changed is sf-if-nonbool (error only; auto-
captured by gen-examples, updated by regen).
