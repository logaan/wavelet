=== 5.1 EVACUATION — DESIGN CHOICE (recorded; deviates from the literal brief) ===
The brief said "canonicalize resource state, land the flat memcpy evacuation."
Working from the actual code I found the literal "flat memcpy at post-return"
under-specifies the problem: (a) resource state is a boxed TAG_CELL/TAG_LIST
graph, not a flat blob; (b) a post-return walk needs a live-root registry the
guest does not have; (c) moving the rep cell breaks the host's handle->rep
mapping. Both the 5a box-graph relocator and the literal 5b canonicalization are
multi-session and risk the PASSING resources callee.

I used a PERSISTENT-REGION + DEEP-COPY WRITE-BARRIER, which reaches the same
payoff with far less risk:
- Resource/functor components reserve [heap_base, arena_floor) (PERSIST_RESERVE
  = 1 MiB) below the arena. Global 0 (arena bump) starts at / resets to
  arena_floor = heap_base + reserve; a new persistent bump global (3+n) grows up
  from heap_base and is NEVER reset. Non-resource components reserve 0 (layout
  unchanged; persist helpers dead).
- persist_alloc(n): bump the persistent region (traps on reserve overflow).
- persist(box): deep-copy a boxed graph OUT of the arena INTO the persistent
  region; interned/already-persistent nodes (box < arena_floor) are kept in
  place, arena nodes copied whole + children re-persisted recursively (null->
  null). Handles every value tag; traps on TAG_FN. Self-recursive.
- Write barrier at the four store sites: cell-new (cell + value persistent),
  cell-set (value through persist), functor set ctor (cell persist_alloc'd,
  empty list persisted), set add (grown list persisted so already-persistent
  elements stay put — only the new element is copied; no O(N^2)).
- Cells are persistent-from-birth so their identity (the rep the handle holds)
  is STABLE — no cell-moving, no registry, no post-return walk.
Then the opt-out guard was removed: every component resets its arena.

Trade-offs recorded for the future: a fixed 1 MiB persistent cap per resource
component (persist_alloc traps past it — fine for conformance / prototype;
growable later); TAG_FN in resource state traps (closures-in-cells unsupported);
the persist deep-copy is the box-graph walk the brief hoped to avoid via
canonicalization — if/when total typing retires boxes, this collapses to the
type-directed flat copy, and the machinery localizes to persist()/the 4 sites.

=== 5.12 VALUES CALLEE — STILL BLOCKED, now on a LANGUAGE decision (new finding) ===
map/filter/fold unblock every LIST function in roundtrip-values.wlt. The ONE
remaining blocker is permissions-rt. The suite transform is a flags complement
(`v ^ all()`, data-dependent). Expressing it needs (i) `flg(list<string>) ->
flags` (construct a flags value FROM A RUNTIME LIST) and (ii) flags MEMBERSHIP.
NEITHER exists in the interpreter/oracle: `flg` is not a builtin (the flg
symbols in src are the wavelet:meta form representation, unrelated), and
`contains` is string-substring only. There is no way in the language today to
build a flags value from data or test membership of a runtime flags value, so
permissions-rt has NO oracle semantics — it cannot be compiled faithfully
("follow the oracle exactly"). This is a LANGUAGE decision for Logan (add
oracle+backend flags builtins), NOT backend codegen. Because a `values` export
is all-or-nothing, the whole callee stays un-buildable and test-values-callee.sh
is deferred. roundtrip-values.wlt header + conformance README updated to say so.
(This corrects the session-15 framing that listed "flg/contains" as backend
