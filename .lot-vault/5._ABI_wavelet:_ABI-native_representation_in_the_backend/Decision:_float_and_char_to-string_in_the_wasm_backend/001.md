# Decision: float/char to-string in the wasm backend

Decision brief for the residue left by goal-5 sessions 9-12: backend `to-string`
traps on floats and chars. **No code was changed** producing this brief;
everything was verified against the current tree (emit.rs `to_str`, value.rs
`write_value`, tests/differential.rs).

## 1. Context — what traps, and what the oracle prints

Sessions 9's two commits made the backend `to_str` helper (`emit.rs`, the
`to_str(box) -> str box` at ~10818) match the interpreter oracle for strings
(quoted + escaped), bools, ints, and every compound value (lists, tuples,
records, variants, flags, cells — nested). But its final arm handles only
`TAG_INT`:

```
// emit.rs:11152-11158 — "anything but int from here traps"
LocalGet(tag); I32Const(TAG_INT); I32Ne; If { Unreachable }
```

`TAG_DEC` (float) and `TAG_CHAR` (char) are not handled before that point, so
backend `to-string` **traps (`Unreachable`) on any float or char** — including
any compound value that contains one.

What the oracle prints, and therefore what the backend would have to match
(`value.rs` `write_value`, :259):

- **Float** (`Value::Dec`, :263-273): special-cases `nan` / `inf` / `-inf`,
  otherwise `format!("{f:?}")` — Rust's `Debug` for `f64`, i.e.
  **shortest-round-trip** formatting (Grisu/Ryū-class): the fewest digits that
  parse back to the same `f64` (`0.1` => `"0.1"`, `1.0` => `"1.0"`,
  `1e300` => `"1e300"`). This is a substantial algorithm.
- **Char** (`Value::Char`, :274): `format!("{c:?}")` — Rust `char` `Debug`:
  single-quoted with escaping (`'a'`, `'\n'`, `'\''`, `'\u{7f}'`, unicode
  passthrough). Requires UTF-8 encoding of the scalar plus the debug escape set.

## 2. Why it's stuck (the harness can't discriminate)

`tests/differential.rs` compares backend `to-string(Do[..])` output
**dynamically** against the interpreter (`print_value`), with a ratchet — but
only over **documented examples**. No non-float/non-char example produces a
float or char to-string, so only 2 SKIP entries remain, both floats — `sf-def`,
`std-div-float` — tagged `TOSTR_TRAP` ("backend `to-string` still traps on
float/char values (5.6)", tests/differential.rs:38). The harness therefore
**cannot validate** a float/char implementation; you would need hand-built test
vectors asserted directly against `print_value`.

## 3. The question

Do we implement float and char to-string in the wasm backend (and if so how), or
accept/park the trap?

## 4. Options

### (a) Park until goal 6 (where retiring the interpreter forces it)

Goal 6 retires the interpreter, making the backend the sole semantics — which
FORCES this: you cannot ship a language whose `to-string` traps on floats/chars
with no interpreter fallback. Until then floats/chars are rare in documented
examples and the trap is contained (2 SKIPs). Cost now: zero. Note goal 6 implies
the backend must then produce EXACTLY the current oracle output (or the oracle's
spec is redefined), so parking **defers but does not remove** the work — it
assigns it to the interpreter-retirement effort. This is where sessions 9-12 left
it; a reasonable default.

### (b) Implement now: a real shortest-round-trip algorithm in wasm

Port a Ryū (or Grisu) `f64`→shortest-decimal routine — either hand-emitted wasm
in `emit.rs`'s float arm, or a Rust helper compiled into the runtime and called
from `to_str`. Ryū is a few hundred lines plus a lookup table; hand-emitting raw
wasm ops is large and error-prone, a compiled Rust helper is more tractable but
the backend currently hand-writes its helpers. Must match Rust's exact `{f:?}`
(its own shortest-round-trip with specific exponent / trailing-`.0` choices).
Verified by hand-built vectors asserted against `print_value` (NOT the
differential harness). Cost: high (float); the exact-`{f:?}`-match requirement is
the risk. Blast radius: emit + new tests only. Recommend only if goal 6 is
imminent or a real program needs float to-string.

### (c) Implement a simpler deterministic format in BOTH interpreter and backend

Change the ORACLE's float printing (`value.rs` `write_value` `Dec`) to something
hand-implementable in wasm (a fixed/limited-precision decimal, or a defined
shortest-ish format both can produce), then implement that same format in
`to_str`; both agree by construction. Cost: this changes documented example
OUTPUTS (any example printing a float) → `./scripts/regen-examples.sh` +
CHANGELOG (user-visible output change) + docs if any prose shows float output.
Downside: loses Rust's shortest-round-trip (`0.1` might print `"0.100000"`), a
real UX regression in the printed form and possibly a **round-trip** regression
(`read(to-string(x)) != x`) — today the language effectively promises float
round-trip via `{f:?}`. Recommend only if (b) is judged too costly AND a simpler
format is acceptable; weigh whether to-string must round-trip floats.

### (d) Accept permanent divergence (explicit carve-out)

Keep the trap; formalize it in the differential harness (already effectively done
via the 2 SKIPs + `TOSTR_TRAP`). Declares backend `to-string` undefined/trapping
on float/char. Weakens the oracle contract (interpreter and backend must agree on
every program — this admits an explicit exception) and would need the carve-out
documented plus a guard so goal 6 doesn't silently inherit a trapping to-string.
Cost near zero. Acceptable only as an interim; incompatible with goal 6's
single-semantics end state.

### Char, separately (cheaper — consider splitting it out NOW)

Char to-string is MUCH cheaper than float: UTF-8-encode one scalar (≤4 bytes,
straightforward in wasm) plus the `{c:?}` escape set (`\n \t \r \\ \'`, `\u{..}`
for non-printables, single quotes around). **No shortest-round-trip algorithm.**
It can be implemented now (option (b) restricted to char) independently of the
float decision, closing the char half of `TOSTR_TRAP`. The one care point is
matching Rust's `char` `is_printable` table for the `\u{}` cases, but it is
bounded. **Recommend implementing char now regardless of the float decision.**

## 5. Recommendation summary

Default **(a)** — park float until goal 6 forces it — but **split char out and
implement it now** (cheap, closes half the residue). If goal 6 is near, do **(b)**
for float with hand-built vectors. Consider **(c)** only if the exact-`{f:?}` port
is too costly and a defined simpler float format (with regen + CHANGELOG) is
acceptable. Use **(d)** only as a stopgap with an explicit carve-out.

## 6. What to do once answered

- **(a) park:** record the decision here and in the 5.6/goal-5 residue; keep the
  2 differential SKIPs + `TOSTR_TRAP`; ensure goal-6 planning inherits "backend
  to-string must handle float/char." No code.
- **(b) float:** implement Ryū/Grisu (hand-wasm or compiled Rust helper) in
  `emit.rs` `to_str`'s float arm before the trap; match `{f:?}` exactly incl.
  nan/inf/-inf (already special-cased in the oracle — mirror those first, they're
  trivial); add hand-built vector tests (float → expected string) asserting
  equality with `print_value`; remove the float SKIPs when the differential
  examples agree; `cargo test` + differential + conformance (ABI unaffected —
  output only, but re-run). **No `regen-examples`** — a pure backend `to_str`
  change; the differential harness compares dynamically (session 9's mechanism
  note). CHANGELOG **Fixed** (removing a backend trap is user-visible).
- **(c) simpler format both sides:** change `value.rs` `write_value` `Dec` first
  (the oracle), implement the same in `to_str`; `./scripts/regen-examples.sh`
  (float example outputs change) + CHANGELOG **Changed** + docs prose; verify
  round-trip expectations; `cargo test` + differential + conformance.
- **(d) carve-out:** formalize the SKIP/`TOSTR_TRAP` as a documented permanent
  exception; add a note/guard for goal 6; no code beyond harness comments.
- **char (any path):** implement char `to_str` (UTF-8 encode scalar + `{c:?}`
  escaping + single quotes) in the char arm; hand-built vector tests vs
  `print_value`; remove char from the trap; CHANGELOG **Fixed**; `cargo test` +
  differential + conformance.

**Downstream surfaces (CLAUDE.md):** `docs/examples.json` needs regen only for
(c) or if a new float/char example is added; CHANGELOG Fixed/Changed as above;
grammars — no change (output format is not syntax); LSP — no change. Session 9
established that pure backend `to_str` changes need NO `regen-examples` (the
differential harness compares dynamically), so (b) and char do not regen; only
(c) regens because it moves the oracle.
