## Where the project stands (verified against main, 2026-07-07)

The language and toolchain are far along; the original goals 0–7 are done
except for decision-gated tails:

- **Pipeline**: read → expand → interpret/analyze → emit → componentize.
  `src/interp.rs` + `src/builtins.rs` are the permanent **semantics oracle**
  (and the docs-playground engine); the wasm backend (`src/emit.rs`, recently
  split into `src/emit/` submodules) is validated against it by
  `tests/differential.rs` over the documented examples, with a SKIP ratchet.
- **Core language & totality**: core settled (parens are exactly one node — a
  call in eval position, a tuple only under Quote; commas lex as whitespace;
  `If`/`Do` are stdlib macros expanding to Match, not special forms). A total
  type checker exists; `--strict` (any expression typed `Unknown` is an error)
  is **opt-in**; the default flip is decision 0.3. Arrow types (`Type::Fn`),
  zero-capture and capturing-closure devirtualization are landed. Exported def
  bodies are checked against their declared result type with safe
  same-signedness int widening.
- **WIT surface**: everything expressible except constructing a **tuple value
  from computed data** (decision 0.1). User-declared resources (`DefResource`)
  are complete end-to-end (read/interp/check/wit/emit + conformance + docs
  prose) with a small fidelity tail (decision 0.5).
- **Compiled execution**: `wavelet run` and the REPL run on the compiled path,
  falling back per-entry to the interpreter on known holes with a stderr note.
  The differential SKIP list (`tests/differential.rs:56`) is the exact
  burn-down for removing that fallback: `macro-expand` (`expand` is confined
  to macro libraries when building), five float + one char `to-string`
  entries, `std-apply` (record payload applied to a multi-param closure),
  `std-read` (needs a wasm-side reader), `values-atoms` (flag literals
  rejected on one emit path).
- **Conformance** (`conformance/`): the resources callee passes both rust
  seeds. The values callee (`conformance/wavelet/src/roundtrip-values.wlt`)
  type-checks and WIT-synthesizes all 35 exports and is blocked **only** on
  tuple construction; its flags complement is already expressed with zero new
  surface (Match over the 16 declaration-order flags literals, arms ascribed
  `The permissions`).
- **Code review**: a record-only review of the whole tree produced 10
  findings. Three are already fixed on main (the `emit.rs` module split, the
  `Emitter::builtin` split, extensionless shebang scripts — PR #37). The
  remaining seven are restated in full in decision 0.8 for triage.
- **Build/CLI/tooling**: shebang scripts (incl. extensionless), rustyline REPL
  with persistent history, VS Code headless grammar checks — all done.
  Registry fetch of components (`wavelet add`) is blocked upstream: `wkg`
  fetches WIT only, not components.

## Decisions already settled (do NOT reopen; recorded here so context survives archiving)

- **Parens**: `(a)` stays a zero-arg call; parens are never transparent
  grouping and never a tuple literal in eval position.
- **If/Do to stdlib**: done, landed (macros over Match).
- **Binding cleanups**: a single list argument binds to one parameter (no
  positional spreading); only `()` means "no arguments"; float literals are
  rejected as Match patterns at check time. All landed
  (`src/interp.rs::bind_params`, `src/check.rs`).
- **DefResource design**: dedicated `DefResource` form; constructor use-site is
  the type name applied (`counter(10)`); methods `counter/next(c)`; statics
  `counter/sum(vs)`; capitalized reserved keys `New:`/`Drop:`; `Static`
  marker; bare type in param position = own, `borrow(t)` explicit; identity
  equality; opaque `<counter>` to-string; not form-serializable; member result
  types use the `The` ascription convention (no dedicated sugar).
- **Declared-result-type threading**: yes — with safe same-signedness int
  widening, return-type-directed overload resolution in bodies, and new
  legitimate sub-expression errors accepted. Landed.
- **Runtime flags**: no new language surface needed for conformance
  (zero-surface Match encoding verified on both seeds). Ergonomic runtime
  flags ops (`flg` from a list, flags membership) are OPTIONAL future
  ergonomics, not required by anything currently planned.
- **`expand` inside compiled macros**: resolved in code — every macro
  component embeds a guest-internal one-step expander over its own macros,
  locked by `tests/macro_differential.rs::expand_inside_macro_agrees`. On the
  build path `expand` is confined to macro libraries (a documented
  confinement, surfaced in the differential SKIP as `macro-expand`).
