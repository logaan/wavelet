# Bug: multi-payload variant cases synthesize invalid WIT

Pre-existing bug found while researching "0.1 Decision: constructing tuple
values in source" (lot:033lMg3lFvO9LLepj3efMs), update 011. Verified on main
2026-07-07.

## Symptom

A variant case declared with multiple payload types synthesizes invalid WIT.

`DefType mylist [zip(list(u32) list(u32)) other]` synthesizes the WIT variant
case `zip(list<u32>, list<u32>)` — but a WIT variant case takes exactly one
payload type, so the generated world is rejected by wasm-tools.

## Fix options (decide which)

1. Reject multi-payload cases at check time with a clear diagnostic
   ("a variant case takes at most one payload type; wrap several in
   tuple(...)"), or
2. implicitly synthesize the payload as a `tuple<...>` of the declared types
   (and make lift/lower agree on that representation end to end).

Option 1 is the smaller, safer change; option 2 changes the language surface
and needs interpreter + checker + backend + WIT synthesis to agree. Either
way, add a test locking the chosen behaviour.
