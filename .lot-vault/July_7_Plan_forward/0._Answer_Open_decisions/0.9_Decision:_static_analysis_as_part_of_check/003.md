# Plain-language explanation (verified against main 2026-07-28)

## What this Thing is

This one is *not* an open design question — you already asked for static
analysis in the project checks (the trigger: `emit.rs` silently grew to 14k
lines with a 1,750-line method before anyone was forced to notice). The only
thing left to decide is the **enforcement mechanism**.

Verified today: nothing has changed since the writeup — `Cargo.toml` has no
`[lints]` table, there is no `scripts/check.sh`, CI runs tests but no
lint/complexity/coverage gate. The one piece that exists is
`scripts/coverage.sh` (drives cargo-llvm-cov), and it reports without gating.

## The actual question

**How should the limits (function length, file length, complexity, test
coverage) be enforced?**

- **(a) In-repo hard gates, no new tools** — turn on clippy's
  `too_many_lines` and `cognitive_complexity` lints at deny level, add a tiny
  script for file-length (clippy can't do that one), and give the existing
  coverage script a `--fail-under` threshold; wire all of it plus fmt and
  tests into one `scripts/check.sh` that runs locally and in CI. Thresholds
  start wherever the current tree passes, then ratchet down/up — so nothing
  demands an immediate cleanup, but no new monolith can appear silently.
- **(b) Dedicated analyzer tools** (lizard, rust-code-analysis, tokei) —
  more precise metrics, but new non-Rust dependencies for anyone building the
  project, and a second configuration to maintain.
- **(c) Advisory-only CI reports** — numbers get printed, nothing fails.
  History says this stops nobody.

## Recommendation

**(a)**. Suggested starting thresholds: ~150-line functions, cognitive
complexity ~30, ~1,500-line files, coverage pinned at today's measured value
(the implementing session measures first and records the numbers in the
script). Clippy's complexity lint occasionally false-positives — allow
per-function overrides rather than loosening the global number.

Answer with one update: "(a)" (optionally with your own thresholds) / "(b)" /
"(c)".
