# 0.9 Decision: static analysis as part of check

You asked for static analysis to run as part of the project's checks:
no thousand-line functions or multi-thousand-line files, cyclomatic
complexity limits, and % test coverage. (Context: `emit.rs` had grown to
14k lines / a 1,750-line method before it was split — the goal is to make
that impossible to repeat silently.)

## What exists today

- `scripts/coverage.sh` already drives **cargo-llvm-cov** (native target,
  full suite) with terminal/HTML/lcov output — but nothing gates on a
  threshold.
- No clippy/fmt gate in CI; `Cargo.toml` has no `[lints]` table. CI (release
  + docs pipelines) runs tests but no lint step.

## Options

- **(a) Clippy lints + cargo-llvm-cov threshold, wired into one
  `scripts/check.sh` — RECOMMENDED.**
  - `[lints.clippy]` in `Cargo.toml`: `too_many_lines` (function length,
    configurable via `clippy.toml` `too-many-lines-threshold`) and
    `cognitive_complexity` (complexity, `cognitive-complexity-threshold`)
    promoted to `deny`; add `cargo clippy --all-targets -- -D warnings` to
    the check.
  - File length + any other structural rules clippy lacks: a small
    `scripts/ci/lint-structure.sh` (e.g. fail if any `src/**/*.rs` exceeds
    N lines; start N at a value the current tree passes, ratchet down).
  - Coverage: `cargo llvm-cov --fail-under-lines <pct>` reusing
    `scripts/coverage.sh`'s bootstrap; start the threshold at current
    coverage and ratchet up.
  - One `scripts/check.sh` = fmt + clippy + structure + tests + coverage
    gate; run it in CI on every push.
  - Pros: no new toolchain deps beyond what coverage.sh already installs;
    thresholds live in-repo; ratchets prevent regression without demanding
    immediate cleanup. Cons: clippy's cognitive-complexity is nursery-grade
    (occasional false positives — allow per-fn overrides).
- **(b) Dedicated analyzers** (`lizard` or `rust-code-analysis` for
  cyclomatic complexity, `tokei` for size): more precise metrics, but new
  non-Rust tool deps for contributors/CI and duplicate configuration.
- **(c) CI-only advisory** (report, don't fail): no local friction, but
  nothing actually stops the next monolith.

## Recommendation

**(a)**, with initial thresholds chosen to pass the current tree (then
ratcheted): function length ≈ 150 lines, cognitive complexity ≈ 30, file
length ≈ 1,500 lines, coverage `--fail-under-lines` at today's measured
value. The implementing session should measure first and record the chosen
numbers in the check script.

## How to answer

One update: "(a)" (optionally with your own thresholds) / "(b)" / "(c)".
