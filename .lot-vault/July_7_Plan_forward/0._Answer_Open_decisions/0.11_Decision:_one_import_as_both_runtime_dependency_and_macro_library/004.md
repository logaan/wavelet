# Plain-language explanation (verified against main 2026-07-28)

## The background you were assumed to know

A Wavelet library can export two different kinds of things: ordinary
functions your program calls **at runtime**, and macros your program uses
**at compile time**. The import surface treats these as two separate roles,
so a package shipping both must be imported twice — verified in
`docs/docs/language/macros.mdx`, which documents exactly this:

    Import {pkg: "acme:html/dsl" macros: true}   // compile-time: the macros
    Import {pkg: "acme:html/api" as: html}       // runtime: the functions

This works correctly and is documented; the complaint is purely ergonomic —
one logical dependency, two import lines. Collapsing them into a single
import is a real language-design task: one form whose resolution feeds both
the macro expander (at compile time) and the component linker (at build
time), including corner cases like whether a package's macro half may call
its runtime half during expansion.

Also noted in the original writeup for context, no decision needed: fetching
macro components from a registry is blocked upstream (`wkg` fetches WIT
packages only, not components), which is unrelated to this question.

## The actual question

**Design the unified single-import form now, or wait until a real dual-role
library exists?** No published Wavelet library ships both roles today, so
there is currently no consumer to validate a design against.

- **(a) Park.** Keep the documented two-import path. The first real
  dual-role library will reveal which resolution corner cases actually
  matter, and the design happens then, informed by it.
- **(b) Design now.** A single `Import {pkg: … roles: {runtime macro}}` (or
  inferred roles). Touches the reader/expander, dependency resolution, and
  docs — with nonzero risk of designing for the wrong corner cases while no
  consumer exists.

## Recommendation

**(a)** — park. This is the same "let a real use case drive the design" call
as 0.10, and the cost of waiting is two lines of imports.

Answer with one update: "(a)" / "(b)".
