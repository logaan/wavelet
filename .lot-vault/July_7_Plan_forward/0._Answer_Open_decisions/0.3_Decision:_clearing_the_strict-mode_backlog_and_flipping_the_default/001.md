# 0.3 Decision: clearing the strict-mode backlog so `--strict` becomes the default

**The totality end-game.** The accepted plan (already settled, restated here
so it survives archiving): `--strict` shipped opt-in; flip it to the DEFAULT
once the documented-example suite AND the conformance suite pass under it,
then **delete gradual mode entirely** (no lingering second dialect); all new
examples are authored strict-clean so the backlog only shrinks. The flip is
blocked by **17 of 86 documented examples** failing under strict
("cannot infer a static type"). Run
`cargo test --test strict_mode strict_backlog -- --ignored --nocapture`
to reprint the live list.

## How strict works today

`--strict` (parsed in `src/main.rs`) sets a process-wide flag in
`src/check.rs`; any expression the checker can only type as `Type::Unknown`
becomes a compile error. Declaration heads and unexpanded macro calls exempt;
macro output is checked post-expansion.

## The 17, bucketed by what actually clears each (empirically verified)

- **Bucket A (6) — a typed param/ascription alone fixes them; checker
  unchanged**: `map-square`, `std-map`, `std-filter` (type the lambda param),
  `eval-fn-scalar`, `pm-describe`, `pm-none` (ascribe the scrutinee).
- **Bucket B (2) — need typed higher-order builtin signatures; no rewrite can
  fix**: `std-fold`, `std-apply` — `fold`/`apply` result types are hard-coded
  `Unknown` in `check.rs`, so even fully-typed lambdas fail.
- **Bucket C (2) — small example rewrite**: `eval-fn-by-name`,
  `eval-fn-by-order` return an intentionally heterogeneous list; returning a
  record instead passes strict and still teaches call-by-name vs order.
- **Bucket D (7) — need deeper checker/backend work; not rewritable away**:
  `eval-twice` (indirect application through a function-typed *parameter*),
  `sf-fn-adder` (returned capturing closure typing), `eval-apply-list` (list
  of function values, indexed then applied — needs the multi-case
  variant/dispatch closure representation), `tail-count-down` / `tail-sum-to`
  (self-recursion: result type can't be inferred through the recursive call
  and `Fn` has no result-annotation syntax — `Fn {n: s64} s64` parses `s64`
  as the body), `std-cells` (no static cell type: type `cell-new(x)` as
  `cell<T>`, admit `cell(T)` ascriptions), `macro-trylet` (option-typed hole
  in macro expansion).

**Load-bearing consequence: no pure-rewrite path reaches the gate.**
Checker/backend work is mandatory for ≥9 of the 17. The only genuine choice
is pedagogy for the ~6 mainstream higher-order examples: keep them untyped
(inference) or rewrite them with explicit types.

## Options

- **(a) Expected-arrow param inference + typed higher-order builtin sigs**:
  give `map`/`filter`/`fold`/`apply` parametric arrow signatures; push the
  expected arrow onto untyped `Fn`-literal params at call sites; extend to
  user-def higher-order params (clears `eval-twice`). Keeps the docs' untyped
  teaching style. Highest checker cost; clears A+B as-authored; still owes
  bucket D.
- **(b) Typed rewrites only**: cannot reach the gate (B and D still fail);
  changes the teaching style everywhere; forces regen. Only meaningful as
  "(c) with bucket-A typed explicitly".
- **(c) Hybrid — RECOMMENDED**: (a)'s inference for buckets A+B (examples
  stay untyped), record-return rewrite for bucket C (one regen), targeted
  straggler work for bucket D: recursion-aware result inference (prefer over
  new annotation syntax), a static cell type, the macro-expansion option
  hole, plus the two remaining closure-representation slices (capturing
  Fn-literal typing; multi-case variant/dispatch — see also the TAG
  retirement rider below).
- **(d) Flip now with an escape hatch** (per-file gradual pragma): a second
  dialect by another name; contradicts the settled delete-gradual rider;
  totality never actually reached. Not recommended.

## The flip itself, once the backlog is 0

Default strict on; remove the flag branch; **delete gradual mode** (the
`Unknown`-as-top paths in `check.rs` and the boxed-fallback branches that
exist only for them); convert the `strict_backlog` diagnostic into a hard
assertion; confirm conformance under strict; CHANGELOG (flip + removal);
update `type-system.mdx` + any prose describing gradual behaviour. LSP
inherits automatically (shared checker); grammars unaffected.

**Riders that belong with totality** (they wait on the flip, not on you):
retiring the runtime TAG_* boxed representations (possible only when total
typing removes the last boxed producer), the multi-case variant+dispatch
closure representation (deliberately deferred to land WITH retirement — a
parallel representation with zero observable change before then), and
collapsing boundary lift/lower to no-ops.
