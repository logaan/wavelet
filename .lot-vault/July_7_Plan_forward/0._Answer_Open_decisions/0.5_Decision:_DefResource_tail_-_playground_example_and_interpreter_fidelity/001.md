# 0.5 Decision: DefResource tail — playground example and interpreter fidelity

DefResource (user-declared resource types) is complete end-to-end
(read/interp/check/wit/emit, conformance both seeds, docs prose in
`docs/docs/language/type-system.mdx` §"User-declared resources" +
`components.mdx`). Three tail items remain; one answer can cover all three.

## Item (i) — a runnable `<Playground>` docs example

There is no DefResource example in `docs/examples.json` — prose only, static
code blocks. Playground examples run on the wasm-compiled **interpreter**
(DefResource works there), so this is pure authoring + the heavy regen:
add e.g. `E['res-counter']` (construct `counter(10)`, `counter/next` twice,
`counter/value`) to `docs/scripts/gen-examples.mjs`, run
`./scripts/regen-examples.sh` (rebuilds the committed `docs/src/wasm`
artifact + `examples.json`, re-locks `cargo test`), embed
`<Playground id="res-counter">` in `type-system.mdx`. Pick an example that
does NOT depend on items (ii)/(iii) below (no moved-handle reuse, no
observable Drop) so it stays valid whatever you decide there.
**Recommend: do now.**

## Item (ii) — own-consumption is dead plumbing in the interpreter

`ResourceInstance` carries `consumed: Cell<bool>` (`src/value.rs`) and
`unwrap_receiver` traps on a consumed handle (`src/interp.rs`, message "use
of a consumed `<type>` handle…") — but **nothing ever sets `consumed =
true`**. So passing an `own(t)` handle to a free function does not invalidate
the caller's copy in the interpreter, while a real component (the backend +
component-model runtime) traps at the boundary. A latent oracle divergence,
currently unobserved (nothing reuses a moved handle).

Doing it: thread declared `own`/`borrow` param types onto closure params
(they're currently erased in `value.rs` `Param`/`Closure`), set `consumed` in
`bind_params` when binding an own-typed resource arg; `borrow` never
consumes; methods bind `self` as the rep (untouched). Oracle tests → backend
agreement → conformance; CHANGELOG Changed (reuse now traps); makes the
ownership-invalidation prose in `type-system.mdx` true. Medium cost.

## Item (iii) — user `Drop:` bodies never run in the interpreter

The backend emits and exports the dtor (the component-model runtime runs it
at last-handle-drop); the interpreter binds nothing for `Drop` and never
invokes it. A real divergence, unobservable today (the conformance counter
declares no Drop). If done, the firing point is the design question —
**recommended: run every live resource's Drop at component teardown** (end
of `run()`): deterministic, matches "last own handle drops at teardown", no
new surface. Rc-drop hooks are fragile/wrong-timed; an explicit `drop(h)`
surface is new design. Invariants (already checker-enforced): at-most-once,
never for borrows, not user-callable. Oracle test with an observable Drop
(append to a log cell) → backend agreement → conformance; CHANGELOG.

## Recommendation

(i) **do now**. (ii)+(iii) share the "thread resource type/lifetime info into
the interpreter" work: do them **together** if you want the oracle to
honestly model ownership+destructors; otherwise **park both** with an
explicit note that the backend already enforces/runs them and the divergence
is unobservable — acceptable interim, weakens the oracle contract.
