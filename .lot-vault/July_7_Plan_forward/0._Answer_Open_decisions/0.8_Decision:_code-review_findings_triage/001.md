# 0.8 Decision: code-review findings triage (accept/reject)

A record-only review of the whole tree (post goals 5/6/7) produced 10
findings. **Three are already fixed on main** (PR #37): the `emit.rs`
monolith is split into `src/emit/` submodules, `Emitter::builtin` is split
into per-group helpers, and extensionless shebang scripts run
(`src/main.rs::is_script_path`). The remaining **seven** are restated here in
full — accept or reject each; accepted ones get scheduled in the plan.

Overall review health note: no `unsafe` in `src/`, zero warnings, the
canonical-vs-boxed seam is conservative (wrong answers fall back to boxed,
not miscompile).

## F1 — compiled→interpreter fallback re-executes side effects (bug-risk, M)

`runner::run` and `repl::eval_forms` fall back to the interpreter on ANY
compiled-path error, including a runtime trap AFTER the program produced
observable effects — a program that prints then hits a known hole (float
to-string etc.) **prints twice**. The harness can't see it (it compares only
final values). Fix: return a typed stage error from the compiled path and
fall back **only on pre-execution failures** (build/compose/load/
instantiate), never after the guest started running; a mid-run trap surfaces
as an error. (The fallback disappears entirely once the holes close, but
until then this is the correct rule.)

## F2 — persist write barrier breaks cell identity and doesn't guard cycles (bug-risk latent, M)

The persistent-region write barrier (`persist` in the emitter) deep-copies
resource/functor state out of the per-call arena. (1) It copies each
`TAG_CELL` fresh — a graph reaching the same cell by two paths becomes two
independent cells, diverging from the interpreter's `Rc<RefCell>` sharing.
(2) It self-recurses with no visited set — a cyclic graph traps on stack
exhaustion. Narrow reachability today (the functor `set` persists one flat
cell), but this barrier is the contract every future DefResource `New` state
graph relies on. Fix: short-term, document the contract (acyclic, no shared
cells) + reject violating graphs at compile time; long-term, thread an
arena-ptr→persistent-ptr identity map through `persist` (preserves sharing,
breaks cycles).

## F3 — differential harness: docs-only corpus, final-value-only comparison (test-infra, M)

`tests/differential.rs` iterates only `docs/examples.json` and compares only
the final `to-string` string. Effect streams/ordering/duplication and
everything not exercised by a documented example are structurally invisible
— which is exactly why F1 and F2 can hide. Unverified corners include
arithmetic edge cases, out-of-bounds, deep recursion, cell mutation
ordering, and multi-call resource-state persistence. Fix: a docs-independent
`tests/fixtures/` differential corpus exercising the resource/cell/persist
surface incl. multi-call sequences, comparing the **stdout stream** as well
as the final value; optionally a small property/fuzz layer over
arithmetic/list/string ops. Keep the SKIP ratchet.

## F4 — REPL recompiles the whole accumulated session per expression (perf, M)

Every bare expression re-emits and re-instantiates a synthetic program
containing ALL accumulated definitions, via a fresh temp project. Sessions
get progressively laggier. Fix: cache the compiled component and rebuild
only when the def set changed; reuse the instance for expression-only
entries.

## F5 — temp-project build harness duplicated ×3 (cleanup + minor security, M)

`src/repl.rs`, `src/runner.rs`, and `tests/differential.rs` each hand-roll
"stage program into `$TMPDIR/wavelet-<kind>-<pid>-<seq>`, build, run, clean
up", with `to_str().unwrap()` panics on non-UTF-8 paths, predictable temp
names + pre-delete (symlink/TOCTOU footgun on shared hosts), and cleanup
that leaks on panic. Fix: one shared helper returning a typed stage error
(pairs with F1), RAII temp dir (`tempfile`), non-UTF-8 paths as errors.

## F6 — interpreter `neg`/`abs` are unchecked (bug-risk low, S)

`neg`/`abs` use raw `-n` / `n.abs()` while `add/sub/mul/div/rem` are
`checked_*` with a catchable "integer overflow" error. On `n == i64::MIN`
the interpreter panics in debug / wraps in release (backend wraps). Fix:
`checked_neg`/`checked_abs` with the same error, and make the backend agree
on trapping (or explicitly document wrap-for-unary) — unary and binary
overflow should behave the same.

## F7 — `node_types` last-write-wins invariant is informal (robustness, M)

The backend's representation choices read a `node_types` table populated as
a side effect of checking; speculative passes (return-type-directed overload
resolution, signature-result inference) also write it, and correctness rests
on "the authoritative `check_roots` walk re-visits every body afterwards" —
true today, asserted nowhere. Fix: have speculative passes write a shadow
table (only the authoritative walk feeds the backend), or debug-assert the
overwrite; document the guarantee at the field.

## Recommendation

Accept all seven. Priority order: F1, F2, F3 first (F3 is what makes F1/F2
regressions visible), then F5 (shares the typed-stage-error work with F1),
then F4, F7, F6.

## How to answer

One update: "accept all" or "accept all except F…" (with any priority
adjustments).
