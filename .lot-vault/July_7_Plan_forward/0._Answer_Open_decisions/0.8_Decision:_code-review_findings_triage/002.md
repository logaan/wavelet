# Restated: the problem and the question

## Problem

A whole-tree code review produced seven still-open findings (F1–F7, stated in
full in the previous update). None of them can be scheduled into the plan
until you say which ones you actually want fixed — this decision is the
accept/reject gate on each finding.

## The question

**Which of F1–F7 do you accept as work to schedule — and do you agree with
the proposed priority order?** One-line reminders:

- **F1** — the compiled→interpreter fallback can re-run side effects: a
  program that prints and then hits a known hole prints twice.
- **F2** — the persist write barrier duplicates shared cells and stack-
  overflows on cyclic graphs; it's the contract future resource state relies
  on.
- **F3** — the differential harness only runs docs examples and only compares
  final values, which is exactly why F1/F2-class bugs stay invisible.
- **F4** — the REPL recompiles the entire accumulated session on every
  expression, so sessions get progressively laggier.
- **F5** — the temp-project build harness is hand-rolled three times, with
  non-UTF-8 panics and predictable temp paths.
- **F6** — interpreter `neg`/`abs` don't overflow-check at `i64::MIN` while
  all other arithmetic does.
- **F7** — the backend trusts an informal last-write-wins invariant on
  `node_types` that is asserted nowhere.

Recommendation: **accept all seven**, priority F1, F2, F3 first (F3 makes
F1/F2 regressions visible), then F5, F4, F7, F6.

Answer with one update: "accept all" or "accept all except F…" (with any
priority adjustments).
