# Plain-language explanation (all seven findings re-verified on main 2026-07-28)

## What this Thing is

Nothing subtle: a code review of the whole tree produced ten findings, three
were already fixed, and the remaining seven (F1–F7, written out in full in
update 001) are waiting for you to say **accept or reject, per finding**.
Accepted ones get scheduled into the plan; nothing happens until you answer.
The original list was three weeks old, so I re-checked every finding against
today's main — **all seven are still real**. Receipts and plain translations:

- **F1 — the silent fallback can repeat side effects.** `wavelet run` falls
  back to the interpreter on *any* compiled-path error
  (`src/runner.rs:485`), including a crash that happens *after* the program
  already printed something — so the program prints, crashes, re-runs in the
  interpreter, and prints again. Note: this whole mechanism is slated for
  deletion once decisions 0.6/0.7 close the last holes; F1 is the correct
  interim rule (only fall back on failures that happen *before* execution
  starts).
- **F2 — resource state can be silently corrupted by design, later.** When a
  resource's state is saved out of the per-call scratch memory, it's
  deep-copied (`src/emit/helpers.rs:1866`) with no tracking of already-copied
  objects: two references to the same cell become two independent cells, and
  a cyclic structure crashes the copy. Harmless for today's one flat cell,
  but it's the contract every future stateful resource relies on.
- **F3 — the safety net has holes exactly where F1/F2 live.** The
  differential harness only runs the documented examples and only compares
  the final value — printed output, effect ordering, and multi-call resource
  state are invisible. This is why F1 and F2 can't be caught by tests today.
- **F4 — the REPL gets slower the longer you use it.** Every expression
  recompiles the entire accumulated session from scratch (`src/repl.rs`
  header calls this "accumulate-and-recompile"). Fix is caching.
- **F5 — the same temp-dir build harness is hand-written three times**
  (`src/repl.rs`, `src/runner.rs`, `tests/differential.rs`), with
  predictable temp paths and panics on non-UTF-8 paths. No `tempfile` dep in
  Cargo.toml. Fix shares the typed-error refactor F1 needs.
- **F6 — two arithmetic builtins skip the overflow check.** `neg`/`abs` use
  raw negation (`src/builtins.rs:400-404`) while every other arithmetic op
  uses checked variants; `neg(i64::MIN)` misbehaves. A ten-minute fix.
- **F7 — the backend trusts an unstated invariant.** Representation choices
  read a type table (`src/check.rs:522`) that speculative checker passes
  also write; correctness rests on "the final authoritative walk overwrites
  everything", which is true today but asserted nowhere.
