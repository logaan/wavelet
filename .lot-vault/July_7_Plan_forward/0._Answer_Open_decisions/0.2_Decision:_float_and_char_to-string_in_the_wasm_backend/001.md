# 0.2 Decision: float and char to-string in the wasm backend

**Gates: removing the run/REPL interpreter fallback** (six of the ten
differential SKIP entries are this). Verified against main 2026-07-07.

## Context

The backend `to_str` helper matches the interpreter for strings
(quoted+escaped), bools, ints, and every compound value — but its final arm
handles only `TAG_INT`; **any float (`TAG_DEC`) or char (`TAG_CHAR`) value,
including inside a compound, traps `Unreachable`**.

What the oracle prints (`src/value.rs::write_value`), which the backend must
match:

- **Float**: `nan`/`inf`/`-inf` special-cased, otherwise Rust's `{f:?}` —
  **shortest-round-trip** formatting (Ryū/Grisu-class: fewest digits that
  parse back to the same f64; `0.1` → `"0.1"`, `1.0` → `"1.0"`). A
  substantial algorithm, and the language today effectively promises float
  round-trip via this format.
- **Char**: `{c:?}` — single-quoted with the Rust debug escape set (`'a'`,
  `'\n'`, `'\u{7f}'`, unicode passthrough). Much cheaper: UTF-8-encode one
  scalar (≤4 bytes) + a bounded escape table. No round-trip algorithm.

Six documented examples sit on the differential SKIP list for this
(`tests/differential.rs`: `sf-def`, `sf-let`, `std-char-conv`, `std-conv`,
`std-div-float`, `std-pi`, reason `TOSTR_TRAP`); the programs build — only
runtime printing traps, so `wavelet run`/REPL fall back to the interpreter
for them. The differential harness compares dynamically, so a pure backend
`to_str` change needs **no** regen-examples; only option (c) below (which
moves the oracle) would regen.

## Options

- **(a) Park float until fallback removal forces it.** Zero cost now; the
  work is assigned to the fallback-removal step (a language whose `to-string`
  traps on floats can't drop its fallback). Defers, doesn't remove.
- **(b) Implement float now**: port a Ryū/Grisu shortest-round-trip routine —
  hand-emitted wasm is large and error-prone; a small Rust helper compiled
  into the runtime is more tractable but the backend currently hand-writes
  its helpers. Must match Rust's exact `{f:?}` (its specific exponent /
  trailing-`.0` choices — this exactness is the risk). Verified by hand-built
  vectors asserted against `print_value` (the harness can't discriminate —
  only two float examples exist). CHANGELOG Fixed.
- **(c) Simpler deterministic float format in BOTH interpreter and backend**
  (e.g. fixed precision): changes documented outputs → regen-examples +
  CHANGELOG Changed + docs; loses shortest-round-trip (`0.1` might print
  `"0.100000"`) and possibly `read(to-string(x)) == x`. A real UX regression.
- **(d) Permanent carve-out**: formalize the trap as documented behaviour.
  Weakens the oracle contract; incompatible with ever removing the fallback.
- **Char, separately — recommend doing NOW regardless**: bounded, no
  algorithmic risk (UTF-8 encode + `{c:?}` escapes + Rust's printable table
  for `\u{…}` cases), closes the char half (`std-char-conv`). Hand-built
  vector tests vs `print_value`. CHANGELOG Fixed.

## Recommendation

**Char now; float = (a) park, executed as (b) inside the fallback-removal
step** (a compiled-into-the-runtime Rust helper, not hand-emitted wasm, with
hand-built vectors incl. nan/inf/-inf). Pick (c) only if you're willing to
change the printed float format language-wide.

"(d)" / "(b) now".
