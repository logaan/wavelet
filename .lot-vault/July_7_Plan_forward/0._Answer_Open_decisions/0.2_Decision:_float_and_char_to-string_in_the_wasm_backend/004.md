# Answering 002: where the stdlib lives, and the "Rust component" idea

## Is the standard library Rust or Wavelet?

Rust — implemented **twice**, once per pipeline:

- **Interpreter**: every builtin in `src/builtins.rs` is a Rust match arm
  (`"to-string" => Ok(Value::Str(print_value(&arg)))`, which is
  `value.rs::write_value` — i.e. Rust's own `{f:?}`).
- **Backend**: the same builtins are **hand-emitted wasm instructions** in
  `src/emit/` (`helpers.rs` builds the runtime `to_str`, `eq_raw`, alloc, …
  opcode by opcode). Nothing is compiled *from* Rust into the component.

The only Wavelet-authored stdlib is the two bundled macros (`If`, `Do`),
embedded as Wavelet source strings inside `builtins.rs`. And note
`wavelet:std/core` is a *name*, not an artifact: it appears nowhere in `src/`
— builtins are compiled inline into every component, and the synthesized WIT
world contains no std import. Every Wavelet component is currently
**self-contained** modulo `wasi:*` and its own sibling imports.

## Does float to-string need to be in the core language?

The *interface* does: `to-string` is a builtin, and the runtime `to_str`
helper is one dynamic function over tagged boxes — it can't know statically
whether a float will show up (inside a list, a record field, …). So every
emitted component needs the float path reachable, unconditionally.

But the *implementation* does not need to be hand-emitted wasm. That's the
useful half of your idea.

## Could it be a separate Rust-written component?

**As a visible composed component: works mechanically, but I'd advise against.**
The machinery exists — `wavelet build` already composes sibling components via
`wac`, and a Rust-built component is just another export to plug ("main can't
tell which of its imports is foreign"). But because `to_str` can't rule floats
out statically, **every** component's synthesized world would grow a
`wavelet:std/fmt`-ish import. That changes `wavelet wit` output for every
program, ends the "single file → self-contained component" property, breaks
the toolless/no-`wac` build path and the hermetic single-component tests, and
makes every embedder responsible for wiring a formatter.

**As a Rust-compiled core module linked *inside* the component: this is the
good version, and it makes option (b) much less risky than the note assumed.**
A component may contain several core modules wired internally — such wiring is
invisible in the WIT world. And the hook already exists in our encoder:
`emit.rs` componentizes via `wit_component::ComponentEncoder`, whose
**adapter-module mechanism** links an extra core module whose exports satisfy
the main module's imports (it's how `wasi_snapshot_preview1` adapters work),
including letting the adapter import the main module's memory. So:

- Write a tiny `#![no_std]` Rust crate: `fmt_f64(bits: u64, dest: *mut u8) -> len`,
  implemented as `write!(buf, "{x:?}")` — f64's `Debug` impl lives in `core`,
  so no allocator is needed (fixed dest buffer, caller-provided). Wrap the
  `nan`/`inf`/`-inf` special cases around it, or keep those in the emitted
  caller as now.
- Compile it to a core wasm module once (build-time artifact, committed or
  built by a script), feed it to `ComponentEncoder` as an adapter; the emitted
  `to_str` float arm calls the import instead of trapping.
- The component's world is **unchanged**; nothing new to compose or host.

The decisive property: the oracle *is* Rust `{f:?}` (`value.rs::write_value`),
so a helper that literally calls Rust `{f:?}` matches it **by construction,
forever** — no Ryū port, no "match Rust's exact exponent/trailing-`.0`
choices" risk, which was the whole risk column of option (b). Costs to be
honest about: a new build-time artifact + toolchain step (`wasm32` target for
that crate), some size (core::fmt's float tables/code, on the order of tens of
KB per component), and the adapter wiring (memory sharing/allocation
discipline between the adapter and our bump allocator) — engineering, but
bounded and testable with the same hand-built vectors vs `print_value`.

## Updated recommendation

Unchanged in shape, better in substance: **char now** (hand-emitted, trivially
bounded, as in the note) — and for float, **(a) park, executed as
(b′): the linked-Rust-core-module variant above** inside the fallback-removal
step, rather than hand-porting a shortest-round-trip algorithm. If you'd
rather not park it, (b′) is also small enough to green-light now. The visible
separate-component variant I'd drop unless you *want* worlds to import a std
formatter.
