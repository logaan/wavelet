# 0.4 Decision: qualified case constructors (`t/east(5)`)

Small, self-contained language question left over from the backend
representation work. Verified against the tree when written (2026-07-06/07).

## Context — how variant/enum cases are constructed today

1. **Bare case constructor — works everywhere.** `DefType` binds each case
   into the value namespace: `DefType ttl [days(u32) forever]` gives `days(5)`
   / `forever`, natively constructed in canonical layout by the backend.
2. **Import-alias-qualified — works, but stays boxed in the backend.** An
   imported `DefType`'s cases bind under the import alias (`sh/circle(2.0)`
   after `Import {pkg: "demo:shapes/api" as: sh}`). Interpreter: plain env
   lookup of the pre-installed `alias/case` binding. Backend: routes through
   dep-call → a TAG_VAR **box** — correct value, never the canonical
   fast-path (the canonical construction gate only matches bare `Node::Sym`
   heads, not `Node::Qsym`).
3. **Type-qualified (`ttl/days(5)`, "case `days` of type `ttl`") — does not
   exist.** Nothing binds it in either engine. The closest precedent is the
   resource-statics spelling `counter/sum(vs)` — but that resolves against a
   resource's member table, and it's also the closest **conflict**: a
   type-qualified case would make variant type names a third occupant of the
   `/` namespace alongside import aliases and resource types, requiring an
   ambiguity/precedence rule.

## Options

- **(a) Drop — RECOMMENDED.** Cases are already constructible two ways.
  Spelling 2 stays correct-but-boxed (a marginal, never-observed missed
  optimization); spelling 3 stays unspelled. Zero code. Optionally one docs
  line stating cases are spelled bare or `importalias/case`.
- **(b) Adopt type-qualified case constructors.** Real new plumbing: thread a
  name→TypeDef map into interpreter Qsym resolution; checker typing; emit
  Qsym routing; and — the crux — settle the `/`-namespace collision rule
  (reject variant-type names colliding with import/resource aliases, or fix a
  precedence) BEFORE any codegen. High design cost, third way to spell an
  existing value, no motivating program. Not recommended.
- **(c) Canonical fast path for spelling 2 only** (pure backend optimization,
  no language change): extend the canonical construction gate to Qsym heads
  resolving to a dep case. Behaviour-preserving; needs instrumentation, not
  diff tests. Worth it only if alias-qualified construction shows up hot;
  otherwise fold into later box-retirement work.

## How to answer

One update: "(a)" / "(b)" / "(c)".
