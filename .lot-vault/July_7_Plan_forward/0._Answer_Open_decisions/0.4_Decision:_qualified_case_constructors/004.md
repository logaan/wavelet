# What is actually being decided

The writeup above gives the background and the answer options but never states
the question. Spelled out, it is two questions — one primary, one secondary:

**Primary: should `typename/case(args)` — e.g. `ttl/days(5)`, a case qualified
by its *type's* name — become a valid way to construct a variant/enum case in
Wavelet?**

Today there are exactly two working spellings for constructing a case:

1. **Bare** — `days(5)`. `DefType` binds each case name directly into the value
   namespace.
2. **Import-alias-qualified** — `sh/circle(2.0)`. For cases of a type imported
   from another package, qualified by the *import alias*.

The type-name-qualified spelling does not exist in either engine. Adopting it
is **option (b)**. Its real cost isn't the plumbing but the design question it
forces: variant type names would become a third occupant of the `/` qualifier
namespace, alongside import aliases and resource types, so a collision /
precedence rule has to be settled before any code is written. And it would be a
third way to spell a value that is already constructible — with no motivating
program on record.

**Secondary (independent): is it worth giving the existing alias-qualified
spelling (2) the canonical fast path in the wasm backend?** It already produces
the correct value, but routes through a dep-call and a TAG_VAR box instead of
canonical layout, because the canonical-construction gate only matches bare
`Node::Sym` heads. Fixing only that — a behaviour-preserving backend
optimization, no language change — is **option (c)**.

So the answers mean:

- **(a)** — "no" to both. Keep the two existing spellings, leave
  alias-qualified construction correct-but-boxed, optionally add one docs line
  saying cases are spelled bare or `importalias/case`. (Recommended in the
  original writeup.)
- **(b)** — "yes" to the primary question: add type-qualified case
  constructors, starting with the `/`-namespace collision rule.
- **(c)** — "no" to the primary, "yes" to the secondary: no new syntax, but
  extend the backend's canonical-construction gate to cover alias-qualified
  case heads.
