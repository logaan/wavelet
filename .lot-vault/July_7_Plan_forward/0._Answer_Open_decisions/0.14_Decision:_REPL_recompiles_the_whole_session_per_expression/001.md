# 0.14 Decision: REPL recompiles the whole session per expression

*Broken out of "0.8 Decision: code-review findings triage"

## Problem

Every bare expression entered in the REPL re-emits and re-instantiates a
synthetic program containing **all** accumulated definitions, via a fresh temp
project (`src/repl.rs` — its header calls the strategy
"accumulate-and-recompile"). Compile cost grows with session length, so
sessions get progressively laggier the longer you use them.

## The question

Do you accept this as work to schedule: cache the compiled component and
rebuild only when the definition set changes, reusing the instance for
expression-only entries?

## Recommendation

Accept. Mid priority — the original triage ordered it after F2/F3/F5. Note it
touches the same `src/repl.rs` staging code as F5 (shared temp-project build
harness), so scheduling them near each other avoids reworking the same code
twice.

## How to answer

One update: "accept" or "reject", with any priority adjustment.
