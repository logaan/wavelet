# 0.17 Decision: node_types last-write-wins invariant

## Problem

The backend's representation choices read the `node_types` table
(`src/check.rs:522`), which is populated as a side effect of checking.
Speculative checker passes — return-type-directed overload resolution and
signature-result inference — also write to it. Correctness rests on the
informal guarantee that "the authoritative `check_roots` walk re-visits every
body afterwards, overwriting speculative entries". That is true today but
asserted nowhere: a future checker change could silently violate it and feed
the backend stale speculative types, miscompiling without any diagnostic.

## The question

Do you accept this as work to schedule — and at which depth?

- **(a)** Debug-assert the overwrite and document the guarantee at the field.
- **(b)** Have speculative passes write a shadow table, so only the
  authoritative walk feeds the backend.

## Recommendation

Accept: (a) is cheap insurance; (b) is the structural fix. The original triage
placed F7 near the end of the priority order (ahead of only F6).

## How to answer

One update: "accept (a)", "accept (b)", or "reject".
