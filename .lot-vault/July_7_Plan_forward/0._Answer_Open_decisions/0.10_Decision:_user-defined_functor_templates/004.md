# Plain-language explanation (verified against main 2026-07-28)

## The background you were assumed to know

"Functor template" is jargon for **a generic container** — a component
parameterized by a type, like a set-of-T. Wavelet has exactly one:
`Set`. You write
`Instantiate {pkg: "wavelet:coll/set" with: {elem: T} as: alias}` and get a
working set of whatever element type. But that works only because the
compiler knows `Set` **intrinsically** — its operations are hard-coded in
`src/builtins.rs:81` (`SET_OPS`) and mirrored through WIT synthesis and the
backend by hand. Verified today: that's still the shape; nothing generic
exists behind it.

What does *not* exist: a way for **user code** to declare its own generic
container ("a component with type parameters") in Wavelet source. Building
that for real means designing type-parameter scoping and checking,
WIT synthesis of parameterized interfaces, and per-instantiation code
emission — a substantial language-design project.

## The actual question

**Is that machinery worth building now, and at what level?** Nothing
currently planned needs a second generic container.

- **(a) Park.** Keep the built-in `Set`. When a second container (a map, a
  queue…) is genuinely wanted, let that concrete need drive the design —
  designing generics with zero real consumers is how languages get generics
  wrong.
- **(b) Cheap intermediate, when needed.** Add further *compiler-known*
  containers on the same hard-coded pattern as `Set`. No new language design,
  but every new container is a compiler change, and the pattern never
  becomes available to users.
- **(c) Design user-defined templates now.** A `DefFunctor`-style declaration
  (the prerequisite, `DefResource`, does exist now) instantiated through the
  existing `Instantiate` form. All of the design risk, none of the driving
  use case.

## Recommendation

**(a)** — park. (b) remains the pragmatic escape hatch if a specific
container is wanted before the general feature is designed.

Answer with one update: "(a)" / "(b) when needed" / "(c)".
