# 0.15 Decision: shared temp-project build harness

(lot:033lMgJ9BtS8IZM2KpoBXi), finding F5, at your request. Re-verified on main

## Problem

Three places hand-roll the same "stage the program into
`$TMPDIR/wavelet-<kind>-<pid>-<seq>`, build, run, clean up" dance:
`src/repl.rs`, `src/runner.rs`, and `tests/differential.rs`. Each copy has:

- `to_str().unwrap()` panics on non-UTF-8 paths;
- predictable temp names plus a pre-delete of the target path — a
  symlink/TOCTOU footgun on shared hosts (minor security);
- cleanup that leaks the temp dir on panic.

There is no `tempfile` dependency in `Cargo.toml`.

## The question

Do you accept this as work to schedule: one shared build-harness helper
returning a typed stage error, RAII temp dirs via `tempfile`, and non-UTF-8
paths surfaced as errors instead of panics?

## Recommendation

Accept. The original pairing was with F1's typed-stage-error refactor; F1 has
since been resolved as "drop the fallback" (0.8), which rewrites the same
`src/runner.rs` code — schedule F5 together with (or immediately after) that
removal so the harness isn't refactored twice.

## How to answer

One update: "accept" or "reject", with any priority adjustment.
