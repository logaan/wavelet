Read-only current-tree audit of the seven inventory items:

1. Per-width arithmetic is incomplete: typed integer lowering in src/emit/mem.rs still calls arith_int, whose checked i64 path lives in helpers/numeric.rs. Scalar/canonical paths already exist, but full width-specific specialization is not implemented.
2. Higher-order specialization is incomplete: builtin_higher_order in src/emit/builtins.rs still builds boxed lists and calls callbacks through a table for map/filter/fold.
3. No per-file std:false opt-out implementation or test was found. Builtins remain installed implicitly; the inventory assumption that an opt-out already exists is unverified and should not be advertised.
4. Large-type support remains limited: src/emit/canonical.rs store_to_mem rejects variants/enums with more than 256 cases and flags with more than 32 members. Layout sizing helpers alone do not remove these restrictions.
5. Statically known symbol-headed tuple patterns are handled by pattern_top and pattern_top_mem. The generic boxed pattern helper still interprets a symbol head as a variant case; further removal is representation work, not a claim of a known reachable strict-typed regression.
6. str-cat still calls the boxed strcat2 helper; a canonical-only concatenation path remains future optimization.
7. The qualified-constructor proposal was superseded by decision 0.4: slash normalizes to hyphen and cases are functions. No distinct Qsym fast path should be scheduled.

TAG retirement and multi-case runtime closure dispatch are not silently complete: tags remain, while runtime dynamically selected/stored functions are rejected under the accepted WIT-only language decision. Keep real backend work open; this audit does not implement optimizations or create the originally requested top-level step-7 plan.
