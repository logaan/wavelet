# Decision: DefResource tail — playground example + staged interp semantics

Decision brief for the three items deliberately left after DefResource
(user-declared resource types) landed. **No code was changed** producing this
brief; everything was verified against the current tree (repl + reading
interp.rs/value.rs/emit.rs/runner.rs + docs/scripts/gen-examples.mjs).

## 1. Context — DefResource is landed; three tail items remain

DefResource is functionally complete across read/interp/check/wit/emit +
conformance (4.5 Thing updates 007-012): the suite's `counter` resource compiles,
exports, and passes rust-a/rust-b `run-resources()` both directions. Verified in
the repl: `counter(10)`, `counter/next`, `counter/value`, `counter/sum([..])`,
`to-string(c)` => `<counter>`, identity `eq`. Three tail items were left:

### (i) A runnable `<Playground>` docs example + the heavy regen

There is **no** DefResource example in `docs/examples.json` (grep: 0), even
though prose exists (`docs/docs/language/type-system.mdx`, `components.mdx`) — but
only as static ` ```wavelet ` blocks, not a live `<Playground>`.

Mechanics (from `docs/scripts/gen-examples.mjs` + CLAUDE.md): every runnable doc
example is authored once as `E['id'] = \`source\`` in `gen-examples.mjs`; the
script runs each through the **wasm-compiled interpreter** (`_eval`, i.e.
`eval_snippet`) and records `value`/`output`/`error` into `docs/examples.json`,
which BOTH the docs `<Playground>` and `tests/examples.rs` consume. So a
DefResource playground example is a **pure interpreter exercise** — the playground
never runs the component backend — and DefResource works in the interpreter, so
it will run. `eval_snippet` evaluates a single snippet's pre-expand tree;
`defresource-MACRO` is a core special form, so it evaluates fine.

Cost = the "heavy regen": `./scripts/regen-examples.sh` runs `wasm-pack build
--target web --out-dir docs/src/wasm` (the slow step — rebuilds
`docs/src/wasm/wavelet_bg.wasm`), then `node gen-examples.mjs`, then `cargo
test`. Both the regenerated `examples.json` AND the committed wasm artifact must
be committed. No new language behavior — just authoring + regen.

### (ii) STAGED: trap on use-after-own-consumption at free-function `own` params

The machinery is **half-present but dead**:

- `ResourceInstance` carries `consumed: std::cell::Cell<bool>` (`value.rs`:49),
  always initialized `false` (`interp.rs`:181).
- `unwrap_receiver` traps if `inst.consumed.get()` (`interp.rs`:543-547, message
  "use of a consumed `counter` handle (its ownership was transferred)").
- BUT `consumed` is **never set to `true` anywhere** (verified: no `.set(true)`
  in the tree).

So today: passing an `own(counter)` handle to a free function does NOT invalidate
the caller's handle, and a later use does NOT trap — the check is dead plumbing.
The design (4.5 update 007, decision 3a) asserts "own-consumption is modelled in
the interpreter"; it is **not yet** — that is exactly this staged item (4.5 update
010, residue B: "closures currently erase types," so param-type info isn't
threaded into the interpreter). The backend gets boundary-level ownership
trapping from the component-model runtime at the export edge; the interpreter
(single evaluation, no CM runtime) has no such enforcement. The counter
round-trip never reuses a moved handle, so this is unobserved.

### (iii) STAGED: actually running user `Drop:` bodies

There is a real oracle **asymmetry**:

- Backend: emits the dtor body and runs the user `Drop` (`emit.rs`:6995,
  7019-7028), exported as `{iface}#[dtor]counter`, fired by the CM runtime at
  last-handle-drop.
- Interpreter: binds **nothing** for `Drop` (`interp.rs`:364, `"Drop" => {}`) and
  never invokes it. When a `Value::Resource`'s `Rc` drops, Rust just frees it; no
  user Drop body runs.

So a user Drop body is **silently ignored in the oracle but run in the backend** —
a latent divergence, unobservable for the counter (which declares no Drop). The
design (4.5 update 007, decision 4/4c) explicitly staged running Drop bodies "may
trail the rest of DefResource (the acceptance counter needs none)."

## 2. The question

Which of the three tail items to do, and in what shape: (i) author a runnable
resource `<Playground>` example and pay the regen; (ii) model own-consumption in
the interpreter so the existing trap fires; (iii) make the interpreter run user
`Drop:` bodies, and decide WHEN they fire.

## 3. Options — per item

### Item (i) — playground example

- **Do now (recommended):** add e.g. `E['res-counter']` to `gen-examples.mjs` (a
  small counter: construct, `counter/next` twice, `counter/value`; or
  `counter/sum`), run `./scripts/regen-examples.sh`, commit `examples.json` +
  `docs/src/wasm/*`, embed `<Playground id="res-counter">` in `type-system.mdx`.
  Low risk (interpreter-only, no semantics change); the one cost is the wasm
  rebuild + `cargo test`. It closes the CLAUDE.md "docs downstream surface"
  obligation — DefResource is the only landed feature lacking a runnable example.
  **Pick an example that does NOT depend on staged (ii)/(iii)** (no own-handle
  reuse, no observable Drop), so it stays valid whatever you decide below.
- **Park:** leave static code blocks only. Cheaper now; leaves the feature
  without a runnable example.

### Item (ii) — own-consumption trap

- **Do now:** thread declared `own`/`borrow` param types into the interpreter so
  binding an `own(counter)` arg sets the source handle's `consumed = true`; the
  existing `unwrap_receiver` check then traps on reuse. Requires carrying
  param types on closure params (`value.rs` `Param`/`Closure` currently erase
  them — 4.5 residue B) and marking consumption in `bind_params`. Semantics
  choices: (1) trap message — already exists, keep it. (2) Fires only at
  `own`-typed *free-function* params (the boundary concept); `borrow` never
  consumes; methods take `self` as the rep (not a fresh handle), so intra-guest
  sibling passing is untouched. (3) Backend agreement: the CM runtime already
  traps at the boundary, so this change makes the oracle *match* the backend.
  Testing: interpreter oracle test (own reuse traps; borrow does not) → backend
  agreement → conformance. CHANGELOG Changed (user-visible: reuse now traps).
  Medium cost (closure param-type threading). This is an oracle-faithfulness
  fix, not user-facing sugar.
- **Park:** leave `consumed` dead. Own-consumption stays unmodeled; a program
  that reuses a moved handle "works" in the interpreter but traps in a real
  component — a latent divergence, acceptable only while nothing exercises it,
  but it weakens the oracle contract.

### Item (iii) — run Drop bodies (and decide WHEN)

The interpreter has no component-model handle lifetime, so the firing point is
the real decision:

- **Explicit drop only:** no explicit-drop spelling exists today (handles drop
  implicitly) → would need a new `drop(h)` surface.
- **Rc-drop hook:** `impl Drop for ResourceInstance` running the body at
  refcount-zero. Problem: no handle to the `Interp`/env at Rust-drop time, and
  `Rc` timing (borrows clone the `Rc`) does NOT match component-model own-handle
  semantics — the body could run at the wrong time or multiple times. Fragile;
  likely the wrong oracle.
- **Component teardown (recommended if doing this):** run every live resource's
  `Drop` at the end of the `run()` entry — matches "the last own handle drops at
  teardown," deterministic, no new surface. Simplest faithful model for a single
  run.
- **Both explicit + teardown:** full fidelity, most work.

Semantics invariants (already enforced by the checker): at-most-once; never for
borrows; not user-callable (`counter/Drop(c)` illegal). Testing: this is an
oracle change → interpreter test with an **observable** Drop (e.g. Drop appends
to a log cell) asserting it runs once at teardown; backend agreement (the CM dtor
already runs — assert the same observable effect); conformance. Because it changes
observable output of any program with a Drop, a documented Drop example →
`regen-examples` + CHANGELOG.

- **Park:** leave `"Drop" => {}`. Interpreter keeps ignoring Drop; backend runs it
  → divergence, unobserved for the counter.

## 4. Recommendation summary

- (i) **DO NOW** — cheap, closes the docs obligation.
- (ii) and (iii) are oracle-faithfulness improvements with **no current
  observer**. Do them together only if you want the interpreter to honestly model
  ownership + destructors (they share the "thread resource type/lifetime info
  into the interpreter" work). Otherwise **park both** with a recorded note that
  the backend already enforces/runs them and the divergence is currently
  unobservable. If you do (iii), **run at component teardown** (deterministic, no
  new surface); defer an explicit-drop surface.

## 5. What to do once answered — per item

- **(i):** add the example to `docs/scripts/gen-examples.mjs`; run
  `./scripts/regen-examples.sh`; commit `docs/examples.json` +
  `docs/src/wasm/*`; add `<Playground>` to
  `docs/docs/language/type-system.mdx`. Verify `tests/examples.rs` green. No
  CHANGELOG (docs only) unless you also reword prose. Grammars/LSP: no change.
- **(ii):** thread declared `own`/`borrow` param types onto closure params
  (`interp.rs`, `value.rs` `Param`/`Closure`); set `consumed = true` when binding
  an `own`-typed resource arg in `bind_params`; keep the `unwrap_receiver` trap.
  Oracle tests (own reuse traps; borrow does not) → backend agreement (a
  component reusing a moved own handle traps both ways) → conformance. CHANGELOG
  Changed. Docs: make the ownership-invalidation prose in `type-system.mdx` true.
- **(iii):** decide the firing model (recommend teardown); implement in the
  runner/interp (run each live resource's `Drop` at end of `run`, discard the
  unit; at-most-once guard); oracle test with an observable Drop → backend
  agreement → conformance; if a documented example gains a Drop, `regen-examples`
  + CHANGELOG Changed + docs prose. Do NOT make `Drop` user-callable.
