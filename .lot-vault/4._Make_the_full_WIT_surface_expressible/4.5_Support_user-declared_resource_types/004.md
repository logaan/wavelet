DefResource sub-decision 1 SETTLED: use-site spelling.

Question: how are a user resource's constructor and methods called at a use site?

Decision: option 1a — members are qualified through the resource name, with the
handle passed explicitly as the first argument, and the constructor is spelled
`counter/new(5)` (NOT `counter(5)`).

  Let {c: counter/new(5)}     // constructor
    counter/next(c)           // method: handle explicit as first arg

Reasoning: reads like every other cross-namespace call in wavelet — imports are
`alias/fn(...)` and the set functor is already `pts/new()` / `pts/add(s ...)`,
the exact template. Reuses the existing Qsym node and resolver (interp.rs ~86),
extended to resolve a resource's members locally rather than only import
aliases. No module-scope pollution from generic member names (new/next/value/
sum); two resources with a `next` cannot collide. WIT synthesis marks the `new`
field as the anonymous `constructor(...)` and methods mangle to
`[method]counter.next`, so the qualified source spelling maps 1:1 onto the
boundary names. `counter` stays purely a type name (rejected `counter(5)` —
nothing else in the language makes one name both a type and a value).

Rejected 1b (bare handle-taking `new(5)`/`next(c)`): floods module scope with
common words; two resources sharing a method name collide with no recourse.

Remaining queue: 2 self discipline, 3 bare resource name in type position,
4 destructor, 5 statics + export surface, 6 identity equality / to-string.
