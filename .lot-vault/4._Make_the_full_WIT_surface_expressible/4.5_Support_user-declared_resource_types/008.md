Constructor use-site spelling RESOLVED (interactive with Logan, 2026-07-04) —
this closes the one open micro-point flagged in the consolidated design above.

**Constructor use-site spelling is `counter(5)`** (the type name applied), NOT
`counter/new(5)`. This reverses decision 1a's original choice.

Rationale, grounded in the WIT/component-model facts we confirmed:
- A WIT resource constructor is written `constructor(params)` — **anonymous** (no
  member name) and **at most one per resource**. At the boundary it mangles to
  `[constructor]counter`. There is no WIT source name to qualify by; wit-bindgen
  conventionally surfaces it as `Counter::new(...)` in Rust, but that's a
  binding-generator convention, not part of WIT.
- Because the constructor is anonymous and singular, `counter(5)` is unambiguous
  and reserves NO lowercase name — `new`, `next`, etc. all stay free for user
  methods. This is what decision 4's capitalized `New` key was reaching for; with
  `counter(5)` the constructor needs no member name at the use site at all.
- The decision-1a objection ("nothing else makes one name both a type and a
  value") is outweighed here: the constructor is genuinely anonymous and singular,
  `counter(5)` reads as "construct a counter," and type-position (`self: counter`)
  vs eval-position (`counter(5)`) already disambiguate.

**Multiple constructors: not possible** — WIT allows zero or one constructor. The
idiom for alternative constructors is a `static func` returning `own<resource>`.
So our `sum` static IS an alternative constructor; in Wavelet these are spelled
`counter/sum(vs)` (qualified static call), and any further alternates are more
statics (`counter/from-list(vs)`, etc.). Only the single anonymous primary is
spelled `counter(...)`.

Revised spelling summary (supersedes the `counter/new(5)` occurrences in the
consolidated design above and in decision 1a):
- constructor:            `counter(5)`
- method:                 `counter/next(c)`, `counter/value(c)`
- static / alt ctor:      `counter/sum(vs)`
- declaration keys:       `New:` (constructor), `Drop:` (destructor), `Static Fn`
                          marker (statics), `self: counter` first field (methods)

A static body that constructs a counter now reads `counter(fold(values 0 ...))`
rather than `counter/new(...)`.
