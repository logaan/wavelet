Consolidated DefResource design — all six sub-decisions answered

Logan has now answered decisions 3, 4, 5, and 6 (3 was interactive; 0/1/2 were
settled earlier). This update folds the whole thread into one design, notes the
two places where Logan's answers moved off the recommendation, and flags the one
micro-point that his decision-4 answer leaves open before implementation.

## The settled design

### Declaration form (decision 0)
A dedicated `DefResource` top-level form owns the whole resource surface —
constructor, methods, statics, destructor — as one declaration that maps 1:1
onto a WIT `resource { ... }` block.

### Member roles are keyed/marked, not named by lowercase convention (decisions 1, 2, 4, 5)
Inside the braces, a member's ROLE is identified as follows:

- `New:` — the constructor. **Capitalized reserved key** (decision 4).
- `Drop:` — the destructor. **Capitalized reserved key** (decision 4).
- `Static Fn {...}` — a static. `Static` is a **marker head** on the member's
  Fn value (decision 5a).
- everything else — an instance method, whose first field must be `self: <resource>`.

```wavelet
DefResource counter {
  New:   Fn {start: u32} cell-new(start)                 // constructor -> the rep
  next:  Fn {self: counter} Do [ cell-set(self add(cell-get(self) 1)) cell-get(self) ]
  value: Fn {self: counter} cell-get(self)               // method
  sum:   Static Fn {values: list(u32)}                   // static
           counter/new(fold(values 0 wrapping-add))
  Drop:  Fn {self: counter} log("counter freed")         // optional destructor
}
```

Why capitalized `New`/`Drop` keys instead of reserved lowercase names
(Logan's decision-4 change from recommended 4a): the constructor and destructor
are **anonymous in WIT** (`constructor(...)` / `[dtor]counter`), so they have no
WIT member name to mirror. Capitalized keys can never collide with the lowercase
names WIT gives methods/statics, so Wavelet reserves nothing from the user's
lowercase namespace. They are lightweight markers/keys the checker recognizes,
NOT new special forms in the evaluator. Because `New`/`Drop` are distinct keys
(not stackable prefixes), there is no "what does `New Drop Fn` mean" question.

### self discipline (decision 2b)
A method's first field is spelled `self: <resource>` (field name must be `self`;
annotation must be the enclosing resource's name). In the body, `self` is bound
to THE REP the constructor returned (the cell, for counter) — inside the defining
component the type denotes the rep. No reader change: `self` is an ordinary typed
field; the checker enforces the discipline.

### Static vs method cross-check (decision 5a)
The checker cross-checks both directions:
- a `Static` member that declares `self: <resource>` is an error;
- a non-static, non-New/Drop member that LACKS `self: <resource>` is an error
  ("member must take self: <resource> or be marked Static").
- **`Static` on `New` or `Drop` is an error** (Logan's decision-5 addendum):
  `New: Static Fn {...}` / `Drop: Static Fn {...}` are rejected.

### Destructor semantics (decision 4 / 4c staging)
Absent `Drop` = no-op (rep still freed, as `set` does today). Present `Drop`
takes exactly `self: <resource>`, returns unit, is NOT user-callable
(`counter/Drop(c)` is illegal — the runtime owns when it fires), runs at most
once when the last own handle drops, never for borrows. Implementation of user
destructor BODIES may trail the rest of DefResource (the acceptance counter
needs none), but the key and checker rules land with the form.

### Type positions: own/borrow (decision 3a — Logan: "Adopt 3a")
Bare `<resource>` in a type position (free-function params/results, other Fn
params, DefType payloads) means **own** (ownership transfers, callee will drop),
matching WIT's reading of the same text. `borrow(<resource>)` is explicit and
param-position only (illegal in result or stored position, as WIT forbids).
`own(<resource>)` is accepted as the explicit synonym for bare. `own`/`borrow`
are ordinary names in type-form position — no lexer change.

Folded-in semantics (part of 3a):
- **Own-consumption is modelled in the interpreter** (the oracle): passing a
  handle to an own-typed param invalidates the caller's handle; later use traps,
  matching the canonical ABI's trap on a dropped handle.
- Borrow params never invalidate; checker rejects borrow in result/stored type.
- Inside method bodies, `<resource>` stays the rep (decision 2b); own/borrow
  only exist at the boundary.

### Export surface (decision 5, Half B)
- Bare `Export counter` exports the WHOLE resource as one WIT `resource` block
  (member-by-member export is unexpressible in WIT anyway).
- Record form `Export {iface: "..." name: counter}` controls interface placement.
- An unexported `DefResource` is a legal, purely internal resource (precedent:
  the `set` functor's resource staying inside the guest).
- The suite's free functions (`make-counter`, `bump-counter`, `take-counter`)
  are NOT part of the resource — ordinary `Def`s using decision-3 type spellings,
  exported individually.

### Observable semantics (decision 6 — Logan agreed both)
- **Equality is identity**: two resource values are equal iff same instance
  (matches component-model handle semantics and interp's cell Rc identity).
  `Derive {Eq}` / Ord / Hash / Show over a resource type is a compile error.
- **to-string prints an opaque `<counter>` token** (type name only), following
  the existing closure/case-constructor angle-bracket convention (value.rs).
  Resources are not form-serializable (same error as closures/cells); `read`
  cannot produce one.

## ONE open micro-point before implementation: the constructor use-site spelling

Decision 1a settled the constructor use-site as `counter/new(5)` (lowercase
`new`, handle explicit). Decision 4 then made the declaration KEY the capitalized
`New`. These operate at different sites, but they interact: if the constructor is
CALLED as `counter/new(5)` while a user is free to define a lowercase method
literally named `new`, the two collide at the use site (both resolve to
`counter/new`). Decision 4's whole rationale was to stop reserving lowercase
names from the user.

Recommendation: make the constructor use-site spelling **`counter/New(5)`** too
(capitalized to match its `New` key), keeping lowercase `new` free for a user
method and making declaration and call symmetric. Destructor stays non-callable.

If you prefer `counter/new(5)` to stand (accepting that `new` is then an
effectively-reserved method name), say so and I'll record that instead. This is
the only thing between the design and scheduling implementation.
