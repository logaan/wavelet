## Root cause

Shebang/bare-file execution was gated by `is_script_path` in `src/main.rs`,
which returned true only for a `.wlt`-suffixed first arg. Extensionless
executable scripts (the common Unix shape — an executable named `deploy`) hit
the usage error instead of running.

## Fix

`is_script_path` now runs a first arg as a script when it names an existing file
and is not a bare-word subcommand:

```rust
const KNOWN_SUBCOMMANDS: &[&str] = &[
    "version", "read", "expand", "repl", "wit", "new", "run", "build", "compose",
];
fn is_script_path(arg: &str) -> bool {
    arg.ends_with(".wlt")
        || (!KNOWN_SUBCOMMANDS.contains(&arg) && std::path::Path::new(arg).is_file())
}
```

- `.wlt` kept as a fast-path → `wavelet missing.wlt` still gives run's "cannot
  read" error, not the usage message.
- The subcommand allow-list stops a stray file named `repl`/`build`/... in the
  cwd from shadowing the real subcommand.
