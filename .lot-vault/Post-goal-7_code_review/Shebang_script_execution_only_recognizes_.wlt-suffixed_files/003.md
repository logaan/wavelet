## Change

`is_script_path` (`src/main.rs`) no longer matches only `.wlt`. It now treats a
first CLI arg as a script when it names an existing file and is not one of the
bare-word subcommands:

```rust
const KNOWN_SUBCOMMANDS: &[&str] = &[
    "version", "read", "expand", "repl", "wit", "new", "run", "build", "compose",
];

fn is_script_path(arg: &str) -> bool {
    arg.ends_with(".wlt")
        || (!KNOWN_SUBCOMMANDS.contains(&arg) && std::path::Path::new(arg).is_file())
}
```

`.wlt` stays a fast-path so `wavelet missing.wlt` still reaches `run` and its
"cannot read" error rather than the usage message. The subcommand allow-list
stops a stray file named e.g. `repl` in the cwd from shadowing `wavelet repl`.

Updated the two comments at the dispatch site + the `is_script_path` doc, and
broadened the usage line to `wavelet <file> [args...]`.
