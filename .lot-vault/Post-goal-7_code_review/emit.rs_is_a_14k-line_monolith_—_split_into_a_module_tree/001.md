# emit.rs is a 14k-line monolith — split into a module tree

## What

`src/emit.rs` is a single 14,425-line file. The `Emitter` impl block alone spans
lines ~1499–8075 (~6,500 lines), and the file also holds: WIT-type modelling
(`WitTy`, sizing/alignment/offsets, ~92–650), the feature scanner (~676–723),
the strategy-B macro-component emitter (`mc_*`, ~9730–11646, a second body of
hand-written wasm that walks form trees), the functor `set` resource bodies
(~9311–9722), all helper-function bodies (`emit_helpers`, 11729–13666), and WIT
synthesis (13666–end). Sixteen sessions of accretion live in one translation
unit.

## Why it matters

Maintainability/reviewability: a single file this size is hard to navigate,
review, and reason about; unrelated concerns (ABI sizing math, the box runtime,
the canonical-memory path, pattern matching, builtins, the macro-component
sub-emitter, WIT synthesis) share one namespace and one `impl`. It also makes
merge conflicts between parallel agents likely.

## Suggested change (sketch)

Split into a module tree, e.g.:
- `emit/witty.rs` — `WitTy` + size/align/offset/flatten helpers (92–650).
- `emit/scan.rs` — `Features`/`scan` (676–723).
- `emit/emitter/` — the `Emitter` split by concern: `boxes.rs` (list/rec/var/
  quote box builders), `canonical.rs` (`lower`/`lift`/`store_to_mem`/
  `load_from_mem`/`*_variant_chain`), `pattern.rs` (`pattern*`, `pattern_mem_*`),
  `call.rs`, `builtins.rs` (the `builtin` method — see separate finding).
- `emit/macro_component.rs` — the `mc_*` strategy-B emitter.
- `emit/helpers.rs` — `emit_helpers` + the persist/arith_int/cmp helper bodies.
- `emit/wit_synth.rs` — `synthesize_world_wit` et al.

The `Emitter` methods can stay on one type via `impl Emitter` blocks in several
files. No behaviour change; purely a move + `mod` wiring, verifiable by
`cargo test` + the conformance matrix being byte-identical.

## Severity / effort

refactor / L (mechanical but large; do it as one no-op-behaviour PR so the diff
is reviewable as pure motion).
