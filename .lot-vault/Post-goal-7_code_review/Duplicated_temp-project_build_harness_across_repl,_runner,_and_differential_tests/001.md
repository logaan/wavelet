# Duplicated temp-project build harness across repl, runner, and differential tests

## What

The "build a synthetic single-file program in a private temp dir, run it in the
host, clean up" harness is duplicated three times, nearly verbatim:
- `src/repl.rs:87-119` (`compiled_eval`)
- `src/runner.rs:393-469` (`run_files_compiled`)
- `tests/differential.rs:140-174` (`compiled_eval`)

Each independently: builds a `wavelet-<kind>-<pid>-<seq>` dir under
`std::env::temp_dir()`, `remove_dir_all` first, `create_dir_all(src)`, stages
input(s), calls `build::build_files(&[.. .to_str().unwrap()], out.to_str().unwrap())`,
loads via `HostComponent`, calls the entry, and `remove_dir_all` after.

## Why it matters

- Maintainability: three copies drift independently (the differential and runner
  copies already differ in artifact selection and error text); a fix to one
  (e.g. the fallback rule in the separate bug-risk finding) must be repeated.
- Robustness: `out_dir.to_str().unwrap()` / `path.to_str().unwrap()`
  (`runner.rs:423`, `repl.rs:102-103`) **panic** on a non-UTF-8 temp path; input
  staging uses `to_string_lossy` (`runner.rs:419`) which can silently corrupt a
  non-UTF-8 file name.
- Minor security: the temp dir name is **predictable**
  (`wavelet-run-<pid>-<seq>`) in a world-writable `/tmp`, and `remove_dir_all`
  runs on it before create — a classic symlink/TOCTOU footgun on multi-user
  hosts. The temp dir also leaks if `build_files` panics (cleanup is after the
  closure, no RAII guard).

## Suggested change (sketch)

Extract one helper, e.g. `build::run_snippet_in_temp(program_or_paths, call) ->
Result<Vec<Val>, StageError>` returning a typed stage error (pairs with the
fallback-rule finding), using an RAII temp-dir guard (or the `tempfile` crate)
for unique, non-predictable names and panic-safe cleanup, and propagating
non-UTF-8 paths as errors rather than `unwrap`. All three call sites use it.

## Severity / effort

cleanup / refactor (+ minor security) / M.
