# Emitter::builtin is a single ~1750-line method — split by builtin group

## What

`Emitter::builtin` (`src/emit.rs:6321`) is a single method that runs to ~8075 —
roughly **1,750 lines** in one `match name { … }`. It dispatches every builtin
(cell-new/get/set, rec-val, gensym, expand, the numeric/string/list/variant
ops, to-string, …) inline in one arm-per-builtin block.

## Why it matters

Maintainability: a 1,750-line function is the single hardest thing in the file
to review or modify safely; each new builtin (16 landed across goals 5–7) grows
it further. Local reasoning is poor — helper locals, `nargs`, and control flow
are shared across dozens of unrelated arms. It is also the most conflict-prone
span for parallel work.

## Suggested change (sketch)

Break the `match` into grouped helper methods returning `Result<(), String>`:
`builtin_cell`, `builtin_numeric`, `builtin_string`, `builtin_list`,
`builtin_variant`, `builtin_macro` (gensym/expand/quote), etc., with `builtin`
reduced to a classifier that routes `name` to the right group. Where an arm is
already self-contained (e.g. `cell-new`, `rec-val`) promote it to its own `fn`.
This pairs naturally with the file split (separate finding) — the builtins
group becomes `emit/emitter/builtins.rs`.

## Severity / effort

refactor / M. Pure motion; `cargo test` + differential harness prove
equivalence.
