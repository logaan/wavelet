# REPL recompiles the whole accumulated session on every expression

## What

The REPL evaluates every bare expression by the *accumulate-and-recompile*
strategy (`src/repl.rs:73-119`, `eval_forms` 128-167): `synth_program` emits a
synthetic single-file program = `Package` + **all** accumulated definitions +
`Def repl-eval Fn {} to-string(<expr>)`, and `compiled_eval` runs the **full**
emitter (`build::build_files`) + a fresh `wasmtime` instantiation for that whole
program, on **every** expression entry.

## Why it matters

DX/performance: cost per expression grows with the number of definitions in the
session — each entry re-lexes, re-expands, re-type-checks, re-emits, and
re-instantiates the entire accumulated program, then throws the module away. A
long REPL session gets progressively laggier for trivial expressions, and every
entry pays wasmtime cranelift compile + instantiate latency from cold. It also
writes/reads a temp project per keystroke-entry.

## Suggested change (sketch)

Options, roughly increasing in effort:
- Cache the compiled component and only recompile when `defs` changed; a bare
  expression against an unchanged def set can reuse the instance and only swap
  the `repl-eval` body — or better, keep `repl-eval` taking no state and
  recompile only on new definitions.
- Longer term, an incremental/session-aware compile, or accept the interpreter
  for pure expression echo and reserve the compiled path for definitions. Given
  the compiled path exists to prove oracle parity, at minimum gate the full
  rebuild on `defs` having changed since the last build.

## Severity / effort

refactor (perf) / M.
