# Compiled-then-interpreter fallback re-executes side effects on a mid-run trap

## What

The compiled-first execution paths fall back to the interpreter on **any** error
from the compiled path, including a runtime trap that happens **after** the
program has already produced observable effects:

- `runner::run` (`src/runner.rs:480-491`): `run_files_compiled(paths)` builds,
  instantiates, and calls `run` (via `call_instance`, `src/runner.rs:461-463`).
  On `Err` it re-runs the whole program in the interpreter (`run_files`).
- `repl::eval_forms` (`src/repl.rs:150-164`): same shape per expression.

`run_files_compiled` only distinguishes stages by the `Err` string prefix; the
caller does not. So a program that prints output (WASI stdout) and *then* hits a
decision-gated backend hole (float/char `to-string`, runtime flags, record
`apply`, `read`) prints on the compiled path, traps, and is then **re-executed
from scratch by the interpreter — printing everything again**. Double side
effects, not the "no regression" the comments claim.

## Why it matters

bug-risk, user-visible: duplicated stdout / repeated effects on exactly the
programs the fallback exists to serve (those using a not-yet-compiled feature
after doing I/O). The differential harness cannot catch it — it compares only the
final `to-string` value, not effect streams.

## Suggested change (sketch)

Distinguish **pre-execution** failures (build / compose / artifact-missing /
load / instantiate) from **execution** failures (`call_instance` trap). Fall
back to the interpreter only for pre-execution failures — i.e. when the compiled
program never started running. Concretely, have `run_files_compiled` /
`compiled_eval` return a typed error (an enum or a boolean "reached the call")
instead of a flat `String`, and only `run_files`/`interp.eval` when the failure
was before the guest ran. A trap mid-run should surface as an error, not a silent
re-run. (Once the decision-gated holes close, the fallback goes away entirely —
6.6 — but until then this is the correct-fallback rule.)

## Severity / effort

bug-risk / M.
