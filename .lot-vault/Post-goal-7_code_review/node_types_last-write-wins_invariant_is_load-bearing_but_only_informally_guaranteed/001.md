# node_types last-write-wins invariant is load-bearing but only informally guaranteed

## What

The backend's static-type table `node_types` (consumed by emit.rs to choose
canonical-vs-boxed representations) is populated as a **side effect** of type
checking, with an explicitly documented "last write wins" contract
(`src/check.rs:515-528`). Multiple passes write it: the authoritative
`check_roots` walk (`src/check.rs:824-869`), plus **speculative** passes —
return-type-directed overload resolution (`resolve_overload`,
`src/check.rs:1994+`) and `infer_sig_result` (`src/check.rs:2064+`) — which infer
other defs' bodies while resolving a call site and record node types transiently.

Correctness of the backend's representation choices therefore rests on the
invariant: *every def body is (re-)visited by the authoritative `check_roots`
pass after any speculative pass touched its nodes.* This holds today —
`check_roots` iterates all roots and `self.check`s every `as_def` body, and
`infer_sig_result` is memoised so it runs once — but the invariant is
**informal**: nothing asserts it, and it is spread across three accreted layers
(argument-directed resolution, return-type-directed resolution, sig-result
memoisation) added at different times.

## Why it matters

Maintainability / latent bug-risk: if a future change ever lets a body be typed
*only* speculatively (e.g. a helper reached solely through return-type-directed
resolution and never as a top-level def, or a change to `check_roots`'s
iteration), the backend would silently read speculative node types resolved under
a *different* `expected`, producing a wrong representation with no test signal —
exactly the kind of drift a post-accretion review should flag. It is a
correctness-load-bearing invariant guarded only by prose.

## Suggested change (sketch)

Make the invariant explicit and defended: either (a) have `check_roots` do a
final authoritative re-record pass and debug-assert that every node written
speculatively was subsequently overwritten authoritatively, or (b) have the
speculative passes record into a throwaway `node_types` shadow (as they already
do for `resolved`) and only merge the authoritative walk's results into the table
the backend reads. Document the ordering guarantee at the `node_types` field.

## Severity / effort

refactor (robustness) / M. (No confirmed miscompile today — verified
`check_roots` visits every def body — but the invariant should be enforced, not
assumed.)
