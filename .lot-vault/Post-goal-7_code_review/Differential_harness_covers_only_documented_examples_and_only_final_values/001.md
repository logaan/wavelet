# Differential harness covers only documented examples and only final values

## What

The differential harness (`tests/differential.rs`) — the mechanism that proves
the wasm backend agrees with the interpreter oracle — has two structural
coverage limits:

1. **Corpus = documented examples only.** It iterates `docs/examples.json`
   (`tests/differential.rs:220-241`); the only programs compared against the
   interpreter are the ones authored for the docs. Any behaviour not exercised
   by a documented example is unverified against the oracle.

2. **It compares only the final `to-string` value.** `wrap_snippet` reduces a
   snippet to `to-string(Do [...])` and compares that one string
   (`tests/differential.rs:105-136,204-216`). Effect **streams**, effect
   **ordering**, effect **duplication**, and traps that occur *after* effects are
   invisible; two runs that print differently but return the same string
   "Agree".

Concretely unverified corners include: integer arithmetic edge cases
(overflow/div-0 trap parity is real in `arith_int`, but only where an example
hits it), `neg`/`abs` at `i64::MIN` (see separate finding), string/list
out-of-bounds, deep recursion / stack limits, cell mutation ordering, and — most
importantly — **resource/functor state persistence across calls** (the 5.1
persist barrier, separate finding), which no `examples.json` entry exercises as a
multi-call sequence.

## Why it matters

The interpreter is the semantics oracle (CLAUDE.md); the backend's guarantee is
only as strong as the differential corpus. Whole subsystems that landed in goals
5–7 (canonical memory, the persist barrier, cells, resources) are covered only
incidentally, if at all, and effect-level divergences (see the fallback
double-effect finding) are structurally invisible.

## Suggested change (sketch)

Add a differential fixture set *independent of the docs* (a `tests/fixtures/`
corpus of small programs) that (a) exercises the goal-5/6/7 subsystems directly,
especially multi-call resource-state sequences and cell mutation, and (b)
captures and compares the **effect stream** (stdout), not just the final value,
for at least the programs that do I/O. Consider a small property/fuzz layer over
arithmetic and list/string ops that runs both engines and diffs. Keep the
SKIP-list ratchet.
