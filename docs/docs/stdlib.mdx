# Standard library

The standard library is available in every file. Function names follow WIT identifier rules: use `add` for arithmetic and `lt` for comparison.

The tables describe supported call shapes. Edit an example and choose **Run** to compile and execute it in the browser.

:::note[What "function" means here]
`If` and `Do` are bundled [control-flow macros](#control-flow-macros). Define other conveniences, such as `And`, `Or`, or `Try-let`, with [`DefMacro`](./language/macros). The library also binds `none`, the empty option, and `pi`.
:::

## Control-flow macros

`If` and `Do` are always in scope. Both expand to [`Match`](./language/special-forms#match), which provides the core branching behavior.

### `If`

`If cond then else` selects a branch. The condition must evaluate to a
`bool` (there is no truthiness); a non-`bool` condition is a **compile-time
error**. Only the taken branch is evaluated, and both branches are in
[tail position](./language/tail-calls). It expands to a two-clause `Match`:

```text
If c t e   ==>   Match The bool c [(true t) (false e)]
```

<Playground id="sf-if" />

A non-boolean condition is a compile-time error:

<Playground id="sf-if-nonbool" />

### `Do`

`Do [exprs]` evaluates each expression in order and returns the last value.
Useful for side effects. Takes a single **list**. It expands to nested `Match`
clauses over a wildcard, so every statement runs and the last is the result:

```text
Do [a b c]   ==>   Match a [(_ Match b [(_ c)])]
```

## Predicates

|---|---|---|
| `eq` | `eq(a b)` | structural equality |
| `lt` `le` `gt` `ge` | `lt(a b)` | ordered comparison (numbers, strings, chars) |
| `not` | `not(bool)` | boolean negation |

`eq` is structural across all data types. The ordered comparisons work on numbers, strings, and chars.

| Function | Shape | Result |
|---|---|---|
| `len` | `len(seq)` | number of list or tuple elements, or Unicode scalars in a string |
| `empty` | `empty(seq)` | is it empty? |

## Tuples

| Function | Shape | Result |
|---|---|---|
| `tuple0` … `tuple16` | `tuple2(a b)` | the tuple of exactly those arguments |

Each constructor takes exactly its stated number of arguments. Its result type follows the argument types. To use one in a collection callback, write a function such as `Fn {x} tuple1(x)`. Parentheses in expression position mean a call; see [compound values](./language/values#compound-values).

## Conversion

| Function | Shape | Result |
|---|---|---|
| `to-string` | `to-string(v)` | printed value text; see the serialization limits below |
| `to-u8` … `to-u64`, `to-s8` … `to-s64` | `to-u8(n)` | range-checked integer narrowing (a char gives its codepoint) |
| `to-f32` `to-f64` | `to-f64(n)` | to floating point |
| `to-char` | `to-char(n)` | int codepoint → char (must be a Unicode scalar value) |

<Playground id="std-tostring" />

Floats print to six significant digits, for example `3.14159`, `0.666667`, and `2.5e-7`. This text is not guaranteed to read back to identical floating-point bits. Use a formatting library when you need another precision or presentation.

Resources print as opaque handles, and some printed values cannot be read back with their original type. See [WAVE output compliance](./development#wave-output-compliance).

Parsing source is a compiler operation: use `wavelet read` to inspect its form tree. Runtime source parsing is not part of the language.

## Input / output

The standard library has no I/O builtins. A program that writes to stdout, reads arguments, or accesses other host features imports a suitable WIT interface, such as `wasi:cli/stdout`,
`wasi:cli/environment`, or `wasi:io/streams`, and calls it like any other
[imported component](./components). The `cli` template scaffolded by
[`wavelet new`](./cli#new) shows the pattern: it imports `wasi:cli/stdout` and
`wasi:io/streams`, builds the greeting, and writes it through the stream.

The application host must supply these interfaces. The browser playground and embedded [`wavelet run`](./cli#run) host do not supply external runtime interfaces. Build the component and use a host that implements its imports.

## Meta & reflection

| Function | Shape | Result |
|---|---|---|
| `gensym` | `gensym()` | a new generated name within the current instance |
| `expand` | `expand(form)` | inspect expansion within a macro body |
| `form-kind` | `form-kind(v)` | the kind tag of a value-as-form |
| `rec-key` | `rec-key(record)` | the first field's key, as a name |
| `rec-val` | `rec-val(record)` | the first field's value |


`expand` is a compile-time operation used inside macro bodies; it is not available as a runtime evaluator.

`form-kind` classifies a value the way the reader classifies a form (`"int"`, `"str"`, `"sym"`, `"tup"`, `"lst"`, `"rec"`, …). A quoted call is a tuple, so it reports `"tup"`; `"call"` is reserved for a runtime variant carrying a payload (`ok(1)`):

## Cells

A `cell` is a mutable reference. It is also a common private representation for a [user-declared resource](./language/type-system#user-declared-resources): the resource constructor returns a cell, and its methods read or update it.

| Function | Shape | Effect |
|---|---|---|
| `cell-new` | `cell-new(v)` | a new cell holding `v` |
| `cell-get` | `cell-get(c)` | read the current value |
| `cell-set` | `cell-set(c v)` | overwrite the value (returns unit) |
| `drop` | `drop(value)` | discard a value and return unit; does not invoke a resource destructor |
