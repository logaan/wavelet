---
title: Build and deploy a web app
---

Wavelet produces a WASI 0.2 HTTP component with a separate domain component
composed into it. Start with the HTTP template:

```sh
wavelet new my-site --type=http
cd my-site
scripts/build.sh
wasm-tools validate out/app.wasm
scripts/serve.sh --addr 127.0.0.1:8080
```

Visit `http://127.0.0.1:8080/hello`. Edit `src/greeting.wlt` for domain logic
and `src/app.wlt` for HTTP handling and HTML. Rebuild and restart the server
after changes. The template sets the HTML content type and escapes request
paths before including them in the page.

The native workflow uses `wkg` to fetch WIT dependencies. The compiler composes components in process. Keep `wit/deps` and `wkg.lock` with your application to preserve
its interface versions. Deployment uses the composed `out/app.wasm`, whose
remaining imports are host-provided WASI interfaces.

## Run the checked-in example

The repository includes `examples/http` with locked, vendored WASI interfaces
and a local HTTP smoke test. From the repository root:

```sh
cargo build
export PATH="$PWD/target/debug:$PATH"
examples/http/scripts/build.sh
python3 examples/http/scripts/smoke.py
examples/http/scripts/serve.sh --addr 127.0.0.1:8080
```

The smoke test starts Wasmtime on an available local port, checks a real HTTP
response and its escaped query string, then stops the server. Vendored WIT lets
the build proceed when registry refresh is unavailable; the compiler may print
a refresh warning. Compiled artifacts stay in the example's ignored `out/`.

## Deployment

Deploy `out/app.wasm` to a host that supports the component's WASI 0.2 imports
and the `wasi:http/incoming-handler` export. Check the host's supported interface
versions and configure request routing, capabilities, and TLS for that environment.
Packaging and upload commands depend on the host. Validate the component and
run the local smoke test before deploying.

The local integration suite runs the artifact with Wasmtime. Compatibility with
other hosts depends on their interface and capability support; deployment to a
remote host is not covered by this suite. Hosts exposing different interfaces
require a compatible adapter or backend.

## Validation

The HTTP smoke test checks a local request against the compiled artifact. The broader [development and validation](./development) suite checks synchronous WIT round trips with independent component implementations, including resource ownership and borrowing.
