# Philosophy

Wavelet uses the WebAssembly Component Model as its foundation for data types, interfaces, and composition. This keeps the language small and makes interoperability part of ordinary programming.

## One file is one component

A source file declares a package, imports interfaces, and exports functions or types. The compiler emits a component for that file. Several files become a program when their imports and exports are connected.

An interface describes what a component provides without specifying its implementation language. Replacing a component with another implementation of the same WIT contract does not require rewriting its callers.

## The syntax is WAVE

[WAVE](https://github.com/bytecodealliance/wasm-tools/tree/main/crates/wasm-wave) is a text encoding for Component Model values. Wavelet adds a small set of [reader rules](./language/reader-sugar) for calls, qualified names, and macros. The reader turns these into ordinary forms.

This makes the language **homoiconic**: code has a data representation that programs can inspect and construct. A macro receives source forms and returns a replacement form. The macro component interface represents those forms as a WIT tree, so another language can implement a Wavelet macro too.

## There is no FFI

Wavelet's runtime data types follow WIT. A local string and a string passed to another component have the same language-level meaning, and imported calls use ordinary function syntax.

The compiler still performs the canonical ABI work needed to move values between components. That boundary can copy data. What you avoid is designing a separate foreign-function interface and manually translating between two unrelated type systems.

## One type system, from the core to the edges

The compiler checks expressions before execution and infers types from literals, operations, call sites, and WIT signatures. Lists have one element type, and records have statically known fields. When the available constraints do not determine a type, write an annotation.

Static typing does not eliminate execution failures. Integer division traps, invalid indexing, and host failures can still trap or return errors.

## A small core with explicit trade-offs

[Special forms](./language/special-forms) provide definitions, functions, matching, quotation, and component declarations. `If` and `Do` are bundled macros. Collection functions accept callbacks that the compiler can resolve statically; runtime data cannot store or return functions.

| Choice | Consequence |
|---|---|
| WIT identifiers | Arithmetic uses `add` and comparisons use `lt`; punctuation operators are not names. |
| Fixed macro arity | Parentheses are optional for TitleCase macro calls, but macros must be known before use. |
| Concrete interface types | Templates specialize types during compilation; generic type parameters do not cross component boundaries. |
| Resource handles | Identity and mutable state have an explicit interface and ownership contract. |
| Per-file components | Composition is explicit, and calls across boundaries can copy data. |

See [supported features and limits](./roadmap) for the restrictions to account for when designing a program.
