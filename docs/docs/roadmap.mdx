# Supported features and limits

Wavelet compiles source to WebAssembly components. CLI execution, the native REPL, the browser REPL, and documentation playgrounds execute compiled components. The interpreter supplies reference results for tests and evaluates Wavelet macro bodies during compilation.

## Language coverage

| Area | Supported behavior |
|---|---|
| Syntax | WAVE-based forms, calls, qualified names, call chaining, and arity-based TitleCase macro syntax. |
| Static checking | Homogeneous lists, structural records, annotated and inferred types, overloads, and exhaustive matching. |
| Functions | Direct calls, statically resolved aliases and capturing callbacks, and tail calls within a component. |
| Data and state | Primitive and compound WIT values, cells, user-declared resources, and imported resources. |
| Compile-time abstraction | Local and component macros, the built-in set functor, and file-local `DefFunctor` templates. |
| Components | WIT synthesis, synchronous imports and exports, composition, resource constructors, methods, statics, ownership, and borrowing. |
| Embedding | An in-memory Rust compiler API and a compiler component with an explicit macro-host protocol. |

The runnable documentation examples are checked against the reference evaluator and executed through the browser compiler component. [Development and validation](./development) describes the other conformance checks.

## Restrictions to design around

- **Function values:** functions cannot be stored in runtime data, returned as closures, selected dynamically for later calls, or passed across component boundaries. Use statically resolved callbacks, variant dispatch, or explicit resources.
- **Inference:** annotations are required when expression and call-site constraints do not determine a type. Inference is not a promise that every definition can omit its signature.
- **Resources:** local free functions and callbacks must borrow existing handles. Persisted resource state supports plain data or one outer cell containing plain data.
- **Macros:** expansion is unhygienic, and binding keys must be literal identifiers. Executable macro artifacts are supplied by the project; automatic registry fetching is not a goal.
- **Derivation:** `Derive` is not implemented and is rejected during compilation. Write those operations explicitly.
- **Templates:** user-defined templates are local to the source file that instantiates them.
- **WIT:** async functions, futures, streams, maps, fixed-size lists, and error contexts are unsupported. Canonical memory paths reject variants or enums above 256 cases and flags above 32 members.
- **Package resolution:** supplying multiple versions of the same package is rejected. Resolve the dependency graph to one version before compiling.
- **Host access:** the embedded CLI runner and browser REPL provide no runtime host interfaces. Build an artifact and use a host supplying the imports your application requires.

Automatic conversion of closures into resources and function-style use of single-method resources are not implemented. Neither are a `wavelet add` command or a composition manifest. Use explicit macro paths, WIT dependencies, and the existing `build` and `compose` commands.
