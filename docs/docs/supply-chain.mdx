# Supply-chain security

A component's imports describe what it needs from its environment. A component cannot access files, open sockets, or read environment variables unless the host or a composed dependency provides an interface granting that access.

This makes dependency review concrete: inspect both the component's WIT contract and the implementations wired to its imports. An interface can grant broad authority, so its name alone is not enough to determine what a dependency can do.

## Runtime capabilities

A Wavelet library is a WebAssembly component with explicit imports and exports. When you compose components, matching exports satisfy imports. Any unresolved imports remain requirements for the host or for a later composition step.

For example, a text-formatting component can accept a string and return another string without filesystem or network imports. A component that writes to stdout must import an output interface, such as `wasi:cli/stdout`, and run on a host providing it.

Use [`wavelet wit`](./cli#wit) to inspect the interface synthesized from source. Inspect the final artifact's WIT after composition to see the host capabilities it still requires. The runtime enforces the component boundary; the host determines the authority behind each supplied import.

## Compile-time macro components

An imported macro executes during compilation. Wavelet loads it as a component implementing the [macro interface](./language/macros#macros-as-components): a manifest describes its macros, and an expansion function transforms source forms.

```wavelet
Import {pkg: "acme:html/dsl" macros: true from: "vendor/dsl.wasm"}
```

The native and browser macro hosts instantiate these components with the imports they explicitly supply. Macro code receives no ambient filesystem or network access. An embedding application controls the capabilities of its own macro host through the [Compiler API](./compiler-api).

A macro can still consume CPU or memory, fail to terminate, or generate unwanted code. Review the artifact you load and the code it produces. The browser worker supports cancellation and a timeout; an embedding host should choose execution limits suitable for its environment.

## Dependency artifacts

Projects supply executable macro components using `from:` or the conventional `wit/macros/` directory. The compiler does not automatically download executable macro components from a registry, and that behavior is not a project goal.

WIT dependency fetching is separate: `wkg` retrieves interface definitions and records dependency versions in `wkg.lock`. Those definitions describe functions and types; they do not provide their implementations.

The component boundary applies to code executed as a component. Native build tools, installation scripts, and host implementations run with their own process permissions, so review those parts of the toolchain separately.
