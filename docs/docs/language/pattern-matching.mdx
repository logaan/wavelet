# Pattern matching

`Match value [clauses]` evaluates its input and chooses the first matching `(pattern result)` clause. Pattern bindings are available in that clause's result, which is in [tail position](./tail-calls). All results must have compatible types.

| Pattern | Matches |
|---|---|
| Integer, string, character, boolean, or flags literal | An equal value. |
| A bare name | Any value, binding it to that name. |
| A payload-less case in scope, such as `none` | That case. |
| `ok(n)` or another case pattern | That case, binding or matching its payload. |
| `(ok)` or `(err)` | A payload-less result case. |
| Tuple or list pattern | The same length, matching each position. |
| Record pattern `{key: pattern}` | A record containing the named field with a matching value. |

A parenthesized pattern is interpreted according to the matched type. Against a variant, `(ok n)` matches its case and payload; against a tuple, parentheses destructure positions.

## Every Match must be total

The compiler checks coverage. Booleans, options, results, enums, and variants must cover all their cases, or provide a catch-all. Open-ended domains such as integers, strings, lists, and trees require a catch-all. Nested payload constraints must also leave complete coverage.
