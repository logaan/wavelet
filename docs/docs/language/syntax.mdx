# Syntax & reading

Wavelet builds on WAVE's notation for values. The reader turns surface syntax into a form tree before macro expansion and type checking. Use `wavelet read` to inspect that tree.

## Lexical ground rules

- Ordinary names use WIT identifiers: hyphen-separated words, each entirely lowercase or uppercase, such as `delete-file` and `parse-JSON`.
- WAVE reserves `true`, `false`, `inf`, `nan`, `some`, `none`, `ok`, and `err`. Escape a conflicting identifier with `%`.
- `//` starts a comment extending to the end of the line.
- Commas, spaces, and newlines separate forms. Indentation helps readers but does not define blocks.

## The attachment rule

A `(` immediately after a name begins a call. Whitespace between the name and the parenthesis separates them into different forms. To pass a list or record, put it inside the call parentheses:

```wavelet
f(x y)
f([x y])
f({a: 1 b: 2})
```

The first call has two positional arguments. The second passes one list; the third passes one record. `f()` calls a function with no arguments. Brackets and braces do not attach directly to names.

## Desugaring

A call becomes a tuple with the head in its first position:

| Source | Canonical form |
|---|---|
| `f(x)` | `(f, x)` |
| `f(x y)` | `(f, x, y)` |
| `f([x y])` | `(f, [x, y])` |
| `f({a: 1 b: 2})` | `(f, {a: 1, b: 2})` |
| `f()` | `(f)` |
| `kv/get(x)` | `(kv-get, x)` |
| `x.f(y)` | `(f, x, y)` |

In expression position, a parenthesized form is a call. Parentheses are not transparent grouping. Use a tuple constructor for runtime tuple data, or `Quote` to preserve a source form as tree data:

<Playground id="syntax-quote-call" />

```console
$ echo 'f(x y)' | wavelet read
(f, x, y)
```

The [reader sugar reference](./reader-sugar) covers each transformation.

## The macro sugar

A name containing a TitleCase word, such as `If`, `DefMacro`, or `Try-let`, uses macro-call syntax. The reader lowercases the name, preserves hyphens, normalizes slashes to hyphens, and adds `-MACRO`. Thus `DefMacro` becomes `defmacro-MACRO`, while `Try-let` becomes `try-let-MACRO`.

The reader knows each macro's arity and consumes that many following forms. Parentheses are optional:

```wavelet
If eq(1 1) "yes" "no"
```

reads as:

```text
(if-MACRO, (eq, 1, 1), "yes", "no")
```

A macro must be defined or imported before use so the reader knows its arity. Nested forms consume their own arguments. `If(c t e)` and `If c t e` describe the same call; an explicit payload supplies the arguments directly.

A macro that needs a variable number of expressions can take one list, as `Do [a b c]` does.

## Call chaining

A dot immediately after a form, followed by a name and attached parentheses, inserts the preceding form as the first argument. `1.increment()` is the same call as `increment(1)`.

Chains associate from left to right:

```console
$ echo 'foo(1).bar(2).baz(3)' | wavelet read
(baz, (bar, (foo, 1), 2), 3)
```

This is a syntax transformation. It does not perform dynamic method lookup.
