# Evaluation

Wavelet compiles expressions after resolving names, expanding macros, and checking types. The evaluation rules describe the behavior of that compiled program:

1. Booleans, numbers, characters, strings, and flags evaluate to themselves.
2. A bare name refers to its binding in the current lexical scope. Unbound names are compile errors.
3. A call evaluates its arguments and invokes its statically resolved function. Ordinary call heads are names; qualified spellings such as `kv/get` normalize to `kv-get`.
4. Special forms control how their subexpressions are used. Macros transform source forms before runtime evaluation.

List and record expressions evaluate their elements and fields. A parenthesized expression is a call; use `tuple2`, another tuple constructor, or `zip` to produce a runtime tuple. `Quote` instead preserves source forms as tree data.

## Functions take exactly one value

A call bundles arguments into a value. Zero arguments form an empty tuple, one argument is passed directly, and multiple arguments form a tuple. The `Fn` parameter record describes how to receive them:

- A record argument can bind parameters by name.
- A tuple argument binds multiple parameters by position.
- A sole parameter receives a single value directly, including a list or record.

## No loops, no mutation, no early return

Bindings are immutable. Use collection operations or [tail recursion](./tail-calls) for iteration and [cells](../stdlib#cells) or [resources](./type-system#user-declared-resources) for mutable state. Error propagation can be expressed with `Match` or a [binding macro](./macros#error-propagation-without-early-return).
