# Getting started

## Try it in the browser

The examples throughout these docs compile and run components in your browser. Edit this one and choose **Run**:

<Playground id="gs-hello" autoRun />

The [browser REPL](/repl) has separate editors for reusable definitions and the expression to evaluate. Each run creates a fresh component instance. For a compact introduction to the syntax, follow [Learn Wavelet in Y minutes](./learn-wavelet).

## Install with Homebrew

Install the CLI and language server from the personal [tap](https://github.com/logaan/homebrew-tap):

```console
$ brew install logaan/tap/wavelet
```

This installs prebuilt `wavelet` and `wavelet-lsp` binaries. To build the current `main` branch instead, use `brew install --HEAD logaan/tap/wavelet`.

### External tools

Wavelet compiles and composes components in process. Native dependency fetching uses [`wkg`](https://github.com/bytecodealliance/wasm-pkg-tools), and the scaffolded CLI and HTTP applications use [Wasmtime](https://wasmtime.dev/) to run with WASI interfaces. Install those tools on `PATH` for those workflows. The browser needs neither tool.

## Building the compiler

Wavelet is written in Rust, edition 2024:

```console
$ git clone https://github.com/logaan/wavelet
$ cd wavelet
$ cargo build --release
$ cargo test
```

The binary is `target/release/wavelet`. Add that directory to `PATH` or invoke the binary directly. See [development and validation](./development) for the full contributor toolchain.

## Your first expression

Start the native REPL:

```console
$ wavelet repl
> str-cat("Hello, " "world" "!")
"Hello, world!"
```

Expressions compile to components. Use `Ctrl-D` to exit. For a reusable application, create a project next.

## Hello, world

The CLI template creates two components and scripts to build and run them:

```console
$ wavelet new hello
$ cd hello
$ scripts/run.sh
Hello, world!
$ scripts/run.sh Ada
Hello, Ada!
```

`src/greeting.wlt` contains the domain logic:

```wavelet
Package "hello:greeting@0.1.0"

Export greet
Def greet Fn {name: string}
  str-cat("Hello, " name "!")
```

`src/main.wlt` imports that function and the WASI interfaces for arguments and output. It exports `wasi:cli/run`, the entry interface understood by the CLI host. WASI is one example of an ordinary WIT contract; another host can provide different interfaces.

The project contains:

| Path | Purpose |
|---|---|
| `src/` | Wavelet component sources. |
| `wit/deps/` | Dependency interface definitions fetched by `wkg`. |
| `wkg.lock` | Pinned dependency versions. |
| `scripts/` | Build and run commands. |
| `out/` | Generated components, excluded from Git. |

Keep the dependency definitions and lockfile with your application. `scripts/build.sh` builds the sibling components and composes them into `out/app.wasm`; `scripts/run.sh` also starts Wasmtime and passes through your arguments.

## Run vs. build

| Command | Use it for |
|---|---|
| `wavelet run main.wlt helper.wlt` | Compile and compose files, then call the first file's `api.run` with no arguments. |
| `wavelet build src/*.wlt -o out` | Retain component artifacts for another host or later composition. |
| `scripts/run.sh Ada` in the CLI scaffold | Run the application's WASI entry point with host output and arguments. |

The embedded `wavelet run` host supplies no external interfaces. It can execute a program whose imports are fully satisfied by composition, including programs using local cells and resources. Build a component and choose a suitable host when the program needs filesystem, HTTP, or other host capabilities.

## Editor support

The `wavelet-lsp` language server provides diagnostics, completion, hover, and document symbols. Both editor integrations below include syntax highlighting for `.wlt` files.

### Neovim

The plugin is [`logaan/wavelet.nvim`](https://github.com/logaan/wavelet.nvim). With lazy.nvim or LazyVim, add:

```lua
return {
  {
    "logaan/wavelet.nvim",
    ft = "wavelet",
    init = function()
      vim.filetype.add({ extension = { wlt = "wavelet" } })
    end,
  },
}
```

Put `wavelet-lsp` on `PATH`; the plugin starts it automatically. Homebrew installs it alongside the CLI. You can also build it with `cargo install --path tooling/wavelet-lsp` or download a binary from the [releases page](https://github.com/logaan/wavelet/releases/latest). Set `vim.g.wavelet_lsp_path` to choose a different binary.

### VS Code

Download and unpack the extension, then reload VS Code:

```console
$ curl -L -o wavelet-vscode.zip \
    https://github.com/logaan/wavelet/releases/latest/download/wavelet-vscode.zip
$ unzip wavelet-vscode.zip -d ~/.vscode/extensions/
```

The extension bundles the matching language server. Set `wavelet.lsp.serverPath` to use a different binary or `wavelet.lsp.enable` to disable it. See [tooling](https://github.com/logaan/wavelet/tree/main/tooling) for other installation options.
