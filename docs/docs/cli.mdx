# CLI reference

| Command | Purpose |
|---|---|
| `wavelet new <name> [--type=cli\|http]` | Create a project. |
| `wavelet read [file.wlt]` | Print the parsed form tree. |
| `wavelet expand <file.wlt>` | Print expanded source forms. |
| `wavelet wit <file.wlt>` | Print the synthesized WIT world. |
| `wavelet repl` | Compile and evaluate expressions interactively. |
| `wavelet run <file.wlt>... [-- <args>...]` | Compile, compose, and execute the first file's `api.run`. |
| `wavelet build <file.wlt>... [-o <dir>]` | Write component artifacts. |
| `wavelet compose <entry.wasm> <plug.wasm>... [-o <file>]` | Connect prebuilt components. |
| `wavelet <file> [args...]` | Run a source file as a script. |

Static checking is always enabled. `--strict` is accepted for compatibility and does not enable a different language mode.

## `new`

Create a new directory containing sources, build/run scripts, a README, and a `.gitignore`. The default `cli` template contains a greeting component and an entry component that imports it:

```console
$ wavelet new my-app
$ cd my-app
$ scripts/run.sh Ada
Hello, Ada!
```

The entry exports `wasi:cli/run` and imports standard interfaces for output and arguments. `new` fetches dependency WIT with `wkg` and records versions in `wkg.lock`. The run script builds the components and invokes Wasmtime, passing through arguments.

`--type=http` creates an application exporting `wasi:http/incoming-handler`. Its `scripts/serve.sh` builds and serves the composed component with Wasmtime. See [web applications](./web-apps).

## `read`

Parse a file and print canonical source forms with reader sugar resolved. With no filename, read stdin:

```console
$ echo 'shout("hi")' | wavelet read
(shout, "hi")
```

Use it to inspect call grouping, qualified names, and macro syntax.

## `expand`

Expand macros until no further expansion applies, then print the resulting forms:

```console
$ wavelet expand program.wlt
```

Macro definitions register compile-time transformations and are removed from the expanded runtime source.

## `wit`

Print the WIT world derived from definitions, signatures, types, and exports:

```console
$ wavelet wit shout.wlt
```

A source exporting `shout: string -> string` produces an interface containing:

```wit
interface api {
  shout: func(phrase: string) -> string;
}
```

## `repl`

Enter definitions and expressions interactively. Input continues across lines until a form is complete. Expressions compile to components and run locally:

```console
$ wavelet repl
> add(2 3)
5
> map(Fn {x} mul(x x) [1 2 3])
[1, 4, 9]
```

On a terminal, arrow keys edit the input, `Ctrl-C` abandons the current line, and `Ctrl-D` exits. History is stored under `$XDG_STATE_HOME/wavelet/history`, or `~/.local/state/wavelet/history`. Piped input uses plain input handling.

The native REPL caches up to 32 compiled expression instances. Repeating an expression can reuse its instance; accepting a definition clears the cache, and a runtime failure discards the affected instance. Source definitions are retained for later expressions. Value redefinitions replace the earlier binding.

The [browser REPL](./browser-repl) instead creates a fresh component instance for every run. Both execute compiled code and return compilation errors or traps directly. Printed results have the [serialization limits](./development#wave-output-compliance) of Wavelet's value printer.

## `run`

Compile the supplied files, compose matching imports, and call the first file's `api.run` export with no arguments:

```console
$ wavelet run main.wlt shout.wlt
```

The embedded runner supplies no runtime host interfaces. Use it for programs whose imports are satisfied by composition. Arguments after `--` are accepted but ignored; for host arguments or side effects, build the artifact and use a suitable host, such as the CLI scaffold's run script.

## Running a script directly

An executable source file can begin with a shebang:

```text
#!/usr/bin/env wavelet
Package "demo:hi@0.1.0"
Export run
Def run Fn {} add(1 2)
```

```console
$ chmod +x hi
$ ./hi
```

The shebang is recognized only on the first line. Files need not have a `.wlt` extension. A first argument naming an existing file, rather than a subcommand, follows the same compiled execution path as `wavelet run` and requires an exported `run` entry.

## `build`

Compile files and write their components to `out/`, or to the directory supplied with `-o`:

```console
$ wavelet build src/*.wlt -o out
```

When the selected entry imports sibling source packages, the compiler also writes a composed `app.wasm`. Individual package components remain available separately. Imports not provided by siblings remain requirements for a host or a later composition step.

Compilation and composition run in process. Dependency WIT must be available in the project's `wit/deps/` tree; populate it with `wavelet new` or `wkg wit fetch`. A compilation error is reported before artifact publication begins.

## `compose`

Connect prebuilt components by matching unresolved imports to supplied exports:

```console
$ wavelet compose out/demo-main.wasm out/demo-shout.wasm -o app.wasm
app.wasm
```

The first argument is the entry. The default output is `app.wasm`. Remaining imports are preserved for the host or a later composition. Inspect the resulting WIT contract before choosing a runtime.
